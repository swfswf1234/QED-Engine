## 目标与成功标准

**目标**：把 8903 的「论文探索」从**一键出候选的黑盒**改造为**可审阅的两级界面**——先看
「这次是怎么检索的」（检索计划、方向、重点、前沿还是核心），再看「哪些论文值得采纳」；同时
给已采纳的论文一个**独立栏位**（左树「论文」节点 + 右栏与教程列同形的卡片列）。五项改动：
E1 入口按钮右靠齐并与同排按钮平齐、E2 探索界面分段（新增检索口径段为采纳的前置）、
E3 待选区间准入判据成文、E4 论文详情可看标题/摘要/评审小结、E5 左树论文节点与右栏卡片列。
本文档是这五项的**设计与实施唯一基准**（执行按「实施清单 I1~I7」），实施完成并经用户确认后
才晋升 `design/downloads-ui.md`；未确认前 `design/` 不动。

**成功标准正本在台账行**（ADR 0023）：逐条对照 todo.md `REQ-107` 行「成功标准」列，本壳
不复制判据条目；执行勘查与取证见「过程与证据」节。

## 范围与非目标

**范围**：本壳承载论文线合并基准全文——已交付现状基线（不可回退面）＋设计本体（§1~§10，E1~E5 已按 R1~R6 裁定定稿）＋**实施清单 I1~I7**＋晋升目标与文档同步清单；
晋升落点＝`downloads-ui.md` §3 增论文节点、§4.1 第五展示组改口径、§4.4 整节重写；
`downloads-flow.md` §7.2 补一句「论文栏为派生视图节点，不参与状态机」。

**非目标**：
- **本轮不动代码**：本文档是实施基准，代码按「实施清单 I1~I7」执行，动码前另立唯一开发行 REQ-108；
  本轮交付只有合并基准文档与台账登记。
- **不改 8901 契约**：E2/E3/E4 全部可由现有 8900 透传端点达成（证据见「过程与证据」）。
- **不把无数据支撑的能力写进界面**：「权威」与「中文总结」在现链路**都没有字段**
  （§3.3 两个事实缺口）；处置已裁定——界面不出现「权威」字样（R3）、详情第三段定名「评审小结」
  用现有 `reason` + `risks`（R4）、引用数仅预留展示位不取数（Q1）。
- 不在前端复制服务端评分权重与阈值算法（只消费 `score` / `recommended` / 三维分结论字段）。
- 不给论文节点或论文行引入 `exploration_stage` 六/五态（延续 downloads-flow §7 既有铁律）。
- 不让模型自动下载、自动采纳，或把评审判断写进资源事实。

### 1. 定位与目标

本节是 8903「文档下载管理」中**论文**这条线的界面事实源：论文探索界面的分段与每段内容、
待选区间的准入判据、论文详情可看什么、以及已采纳论文在左树与右栏的栏位形态。

它回答的是「用户如何看清系统按什么口径找论文，并逐条决定要不要把某篇收进书库」——
先**检索方式**，后**采纳判断**，最后**在专属栏位里管理已采纳的论文**。

- **服务对象**：图书馆主理人本人（个人图书馆，无多租户）。
- **成功标准**：① 探索入口在最右侧与其他按钮平齐、三处入口一致；② 点开后先能看清探索方向、
  重点与配方（前沿/核心），任务跑完后**先出检索计划再出候选**；③ 待选区间只放高相关、
  有用的论文，未入选可见但不可勾选；④ 任一条论文能看标题、摘要、评审小结；⑤ 已采纳论文
  在左树有独立「论文」栏位，右栏是与教程列同形的横向卡片列；⑥ 全程只连 8900、不自动下载。

### 2. 范围与非目标

- **本节节管**：入口与按钮位置形态；探索弹窗分段与每段字段；检索口径的可视化词汇；待选区间
  判据；论文详情内容与按需回源规则；左树论文节点语义与右栏卡片列形态；空态与降级矩阵。
- **本节节不管**（事实源改指）：论文链路的任务态/报告态与五层态派生徽标→
  `downloads-flow.md` §7.2；papers 端点形状与错误码→`api-contracts.md` §③；8901 内部检索与
  评分实现→对方 `docs/design/paper-discovery.md`（根侧不复制）；书目详情弹窗通用字段→
  `downloads-ui.md` §4.1 既有正文；论文 PDF 落盘目录与内容身份→`dataset-conventions.md`。

### 3. 检索链路事实（界面必须照此表达）

#### 3.1 一次「论文探索」实际发生了什么

```
提交 recommend（domain_id 必填 + recipe + goal? + categories? + top?/limit?/years_limit?）
  → 端点即校验（未知配方/非法分类/领域不存在 ⇒ 422；同领域同配方同目标在跑 ⇒ 409）
  → 后台任务 paper_recommend：
      ① 模型生成本次检索计划 search_plan（失败则确定性兜底 ⇒ plan_source=fallback）
      ② 按计划逐条到 arXiv 检索（terms 之间 OR，category AND）
      ③ 按 arXiv ID 去重 + 排除已在库论文（excluded_existing）
      ④ 截断至 MAX_CANDIDATES=40 条候选
      ⑤ 模型给每条打三维分（goal_fit / foundational_value / readability，各 0–5 整数）+ 理由 + 风险
      ⑥ 应用层合成 score（三维加权，0–100），≥70 且未超 top 者进 recommendations
  → 报告落库（qt_selections），状态 ranked / no_candidates / no_recommendations / failed
  → 人工逐条 pick ⇒ adopt 建 kind=paper 书行（停在 candidate，**不自动下载**）
  → 显式取书 ⇒ 五层态 candidate→decided→downloading→downloaded→verified
```

界面表达纪律：
- 「检索计划由模型在任务内生成」——发起前**只能**说明口径（年窗/抓取量/分类来源/目标），
  不能预告具体关键词；实际计划只能在任务成功后展示（这是 R1 之外的既有事实，不属待裁）。
- 年窗显示取 `profile.years_limit`（顶层 `years_limit` 不落库）。
- `plan_source` 必须可见：`模型计划`／`兜底计划`（兜底属降级，界面须警示并列出 `search_failures`）。

#### 3.2 每条候选的可展示字段（全部现成，无需新端点）

| 界面项 | 数据源 | 备注 |
| --- | --- | --- |
| 标题 | `candidate.title` | — |
| 作者·年·链接 | `candidate.authors[]` / `.year` / `.page_url` | arXiv 页链接只读展示 |
| **摘要** | `candidate.abstract` | arXiv 原文摘要，非中文、非生成 |
| 评审小结 | `assessment.reason` + `assessment.risks[]` | 现链路**没有「总结」**，用「评审小结」承载（R4） |
| 相关度/基础性/可读性 | `assessment.goal_fit` / `.foundational_value` / `.readability`（各 0–5） | 三维分原样显示，不换算不加权 |
| 总分 | `score`（0–100，服务端已算） | 界面不重算 |
| 是否入选 | `recommended` + `recommendations[]` | 唯一推荐判据来源 |
| 已入库标记 | 书行 `excluded_existing` / 书目桶命中 | 已在库不可再 pick |

#### 3.3 两个事实缺口（不得在界面上假装存在）

- **权威性**：arXiv 适配器未取 `journal_ref`/`doi`/`comment`/`primary_category`，模型评分输入里
  也没有任何引用数或期刊信息，arXiv 本身亦不提供引用数 ⇒ **权威不进门槛、界面不出现「权威」字样**
  （R3 已裁）。用户认可的替代形态「引用数只展示、不筛选」需要**外部数据源**，属新能力面，
  已裁为 Q1＝**暂不做**（2026-10-11）；界面只**预留位置**——字段不存在时整位不显示（**不显示 0**，
  不造数据），本基准不含任何取数工作项。
- **总结**：报告每条只有 `assessment.reason` + `risks`，无摘要生成节 ⇒ 详情第三段定名
  **「评审小结」**（R4 已裁），不写「总结」。

### 6. E3 待选区间的准入判据（R6 已裁：双门槛）

> 第二轮起：**段④的列表判据与头部计数行以 §11.5 为准**（三门槛之上再叠「未在库」）；上表三门槛本身不变。

**待选区间＝同时满足三条**：

| 判据 | 字段条件 | 说明 |
| --- | --- | --- |
| 高相关度 | `assessment.goal_fit ≥ 4` | 三维中唯一表达「与本次探索目标契合」的量表（0–5） |
| 总分抬高 | `score ≥ 80` | 在服务端结论字段上比较，前端不重算权重、不改服务端推荐线（70） |
| 服务端推荐 | `recommended === true` | 服务端事实（`score ≥ 70` 且落在本次 `top` 内）；界面只读布尔 |

- 「有用」由后两条承载；`score ≥ 80` 是**界面层的额外门槛**，与服务端推荐线并存、不互相覆盖。
- **「权威」不进门槛**（R3 已裁）＝门槛只有上表三条；引用数若落地也只展示、不参与筛选（§3.3、§7）。
- 门槛按用户口径刻意收紧（「让系统帮忙筛选，先只要少部分」）：**达线数少是预期结果，不是故障**。

呈现规则：
- 段④头部一行：`候选 N 篇 ｜ 待选区间 M 篇（未达线 N−M 篇）`。
- 待选区间条目**默认全选可改**；未达线条目折叠在「查看未入选」区，**只读不可勾选**（防绕过门槛），
  每条注明**唯一归因**（按顺序取第一个不满足项）：`相关度 x＜4` → `总分 y＜80` →
  `超出本次推荐上限`（`goal_fit ≥ 4` 且 `score ≥ 80` 但 `recommended=false`）。
- 一条都不达线时：段④空态「本次没有达到待选门槛的论文（相关度需 ≥4 且总分需 ≥80）」，
  两个出口——`回段①调参再探`（换配方、放宽年窗、提高 top）与 `查看未入选`。
- 容量提示：达线数受段① `top`（默认前沿 10／核心 8，可提到 20）限制，头部一行给出提高出口——
  端点现成能力，不向对方提参数级请求。

### 7. E4 论文详情（标题／摘要／评审小结）

- **探索段内（尚未采纳）**：点条目 → 就地展开详情卡：标题、`作者 · 年 · arXiv 链接`、
  **摘要**（`candidate.abstract` 全文，原文语言不改写）、**评审小结**（`assessment.reason`
  正文 + `risks` 逐条）、三维分与总分、是否入选。引用数位（Q1 若落地）显示在 `作者 · 年 · arXiv 链接`
  行尾，仅展示不参与任何门槛；现无该字段时整位不显示。
- **已入库（论文栏或行内卡点击）**：书行本身只有书目字段（标题/作者/年/publisher=arXiv/
  五层态/页数/落位）。摘要与评审小结**按需回源**，链路为
  `GET /books/{book_id}/sources`（取 `channel=arxiv` 的 `provider_id`）→ 该领域
  `GET /papers/selections` 摘要列表 → 逐份 `GET /papers/selections/{id}`，在 `candidates`
  中按 `identifiers.arxiv` 匹配 → 命中即并排显示书目 + 摘要 + 评审小结 + 分数。
  - 纪律：**仅在用户点击时发起**、只扫当前领域、扫描份数上限 20 份、失败静默降级、
    不缓存全量报告、不为凑数据轮询多领域。
  - 未命中（早期采纳、CLI 或外部登记、报告已清理）：显示「该论文没有探索记录」，
    书目字段照常，不编造摘要。
  - 若 R3/R4 裁定把摘要或总结落到对方链路（adopt 建行的携带字段），本条改直读、回源作废。

### 8. E5 左树「论文」节点与右栏卡片列

- **树的形态**：每个领域节点下、课程之后，固定追加一个子节点**「论文」**——它是**派生视图
  节点**，不是课程、不落任何课程记录；节点右侧计数＝该领域 `kind=paper` 书行数（含落位到

## 已裁定与悬留项

- **R1（已裁）**：汇总行内右靠齐，且与「当前选择：领域／课程名」文本行**同一排**（形态甲；页头动作组作废）。
- **R2（已裁）**：课程语境保持「取其所属领域」，无领域则置灰；不给课程级独立探索入口。
- **R3（已裁）**：「权威」**不进门槛、界面不出现该字样**；引用数改为**只展示不筛选**——但引用数在现链路
  无数据源（见 §3.3），故记为悬留项 Q1，本轮界面仅预留展示位。
- **R4（已裁）**：详情第三段定名**「评审小结」**（`assessment.reason` + `risks`），不写「总结」，不提生成请求。
- **R5（已裁）**：左树「论文」栏与行内展示行**并存**；栏范围按推荐默认＝该领域全量（含课程落位，卡片带归属标签）。
- **R6（已裁）**：**双门槛** `goal_fit ≥ 4` ∧ `score ≥ 80`，并要求服务端 `recommended`；门槛收紧是有意选择
  （「先只要少部分」），配套未入选折叠区、逐条唯一归因、以及段① `top` 提高出口。
- **Q1（已裁＝①）**：论文「引用数」**暂不做、界面仅预留展示位**——不提跨项目请求、不由根侧自行取数，
  引用数不参与任何门槛；字段不存在时整位不显示（不显示 0）。现链路确无该数据（arXiv 不提供引用数，
  适配器与模型评分输入均无该字段），故本文档不含任何取数工作项；日后若要做，先改本文档再动码。
- **R7（已裁）**：段①「领域目标」改名**「领域描述」**，仍只读展示 `domain.description`。
- **R8（已裁）**：检索方向四值（前沿／核心／深度／匹配）＝**根侧参数映射**（`recipe` 别名复用 + `top`／`limit`／
  `years_limit`／`goal` 覆盖，见 §11.2）；不向 8901 提请求、不改 `RECIPES` 值域、不改 `api-contracts.md`。
- **R9（已裁）**：**推荐上限不再展示**（用户口径「选默认值即可不需要展示出来」），一次探索固定 5 篇（`top=5`）。
- **R10（已裁）**：段④「未判别」＝**未采纳且达线**；「剔除已选择」＝后端剔已入库 ∧ 前端剔已采纳（§11.5 分工）。
- **本文档无其余悬留项**：晋升唯一前置是「实施清单 I1~I12 全部做完 + 用户确认」。
