## 目标与成功标准（含背景）

**背景**（用户发令 2026-09-24，四项裁决已拍板）：
① 控制台资源监控饼图只有聚合「模型占用」片，不标注是哪个模型；且 admin-console §3.3
仍写「进程列表」，与 2026-09-06 三片饼图实现双向漂移（取证：`GpuOverview.tsx` 头注释与
`GpuOverview.test.tsx` 断言「无模型进程清单」；后端 `/monitor/gpu` 进程数据其实一直在返回）；
② 刷新慢实测：`/monitor/gpu` 单次 **3.9s**（两次重复一致），其余 6 端点 0.03–0.2s；
内部拆解＝两次串行 `powershell Get-Counter`（PDH 显存 + PDH 利用率）各 ~1.5s 占绝对大头，
nvidia-smi×2 仅 0.07s、tasklist 0.03s 可忽略。前端 `fetchAll` 用 `Promise.all` 全部到齐
才一次性提交，秒回的服务徽章也被 GPU 探针拖到 ~4s；
③ 仪表盘按用户裁决改为**三大块**：服务详情（服务在线 + 本地模型状况）/ 文档下载 /
文档解析情况（当前缺失）；现「三行×N 领域」饼图在单领域现状下信息密度过低。

**目标**：管理台「看得清（哪个模型占多少、解析推到哪）+ 刷得快（首屏不被 GPU 探针拖死）」。

**成功标准**：

### A. 仪表盘三块制（重写 admin-dashboard.md §3 布局）

单屏自上而下三块，全部只读（操作归控制台）、全部经 8900：

1. **块一 服务详情**（合并现「服务在线情况」卡 + LocalModelStatus 卡 + 补水位行，一张卡三段）：
   - 段 1：四服务徽章行（现状保留，`withWebServiceFallback()`）；
   - 段 2：本地模型状况——现 `LocalModelStatus` 组件整体并入本卡（ARCH-028 显隐/单双卡规则不变）;
   - 段 3：一行水位：MySQL 状态（`dbStatus`）+ 显存 已用/总 + 利用率（`gpu`）+「在跑：槽位·身份名」
     （与 S3 共用派生函数）。数据全部来自 `useRuntimeStore` 既有字段，30s 轮询保鲜现状不变。
2. **块二 文档下载**：四统计数字保留；**三行饼图 → 每领域一张卡、卡内两根堆叠横条**
   （探索/课程推进一条 + 书籍下载 5 态一条，ECharts stacked horizontal bar，tooltip 带数、
   条上标计数标签）；5 态口径与颜色对齐现 §3.5 表（未开始/下载中/待验证/完成/失败，
   parallel/retired 不计入），聚合函数改造为输出堆叠条数据结构，旧饼图聚合退役。
3. **块三 文档解析情况（新增）**：数据源 `GET /parse-jobs`（现成，每书取最新 job）+
   `GET /books`（af_books 书目归属）：
   - KPI 行：书目总数 / 已完成（最新 job completed）/ 进行中（queued·running 置顶列出，
     `parsed/total` 进度）/ 失败页数合计；
   - 每书堆叠横条：parsed / failed（含 partial 残页）/ total 空白 三片，按书目分组，
     状态标签＝已完成·partial·进行中·未开始；
   - 降级：8902 离线 → 块三警告横幅 + 隐藏图表（独立性铁律），不阻塞块一二。

### B. 资源监控「在跑模型」标注（admin-console §3.3 小修，BUGFIX-017）

- GPU 卡指标行下增一行「当前在跑」：由 `slots`（store 已有，零新请求）派生——
  每个 `source=local 且 ready` 槽位显示「槽位·身份名（渠道）」；全 api 显示「（API 模式）」；
- 饼图保持三片聚合，「模型占用」片 tooltip 追加在跑身份名；
- §3.3「进程列表」过时表述更正为三片饼图现状口径；进程级明细仍不上 UI（REQ-038 用户
  裁决「颜色图例即可」不变），原始进程名保留在 `/monitor/gpu` 响应供诊断。

### C. 刷新性能（前后端，用户裁决「一起修」）

- 后端 `probe_gpu`：PDH 两计数器合并为**一次** `Get-Counter -Counter a,b`（省一次 PowerShell
  冷启动）；`/monitor/gpu` 端点加 TTL≈10s 结果缓存 + 单飞（并发只跑一次探针，其余返回缓存），
  多客户端轮询（控制台 60s、仪表盘 30s、ResourceWatch 10s、手动刷新）合流；
- 前端 `fetchAll`：八路 fetchOne 改为**各自到达即 set 对应字段**（错误仍 per-field 降级），
  `loading` 语义不变；GPU 卡自身 loading 由 `gpu===null` 推导；
- `store 语义`回核 admin-console §5/§6「fetchAll 并行 7 请求」表述微调为增量提交。
