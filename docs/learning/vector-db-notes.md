# 向量数据库笔记

个人学习资料，不参与工程治理。

## 定位

向量数据库存储"文本 → 嵌入向量"的映射，提供**近似最近邻（ANN）检索**：给定查询向量，
返回最相似的 k 个向量及其原文。核心是索引结构与相似度度量，不是数据库事务。

## 常用方案对比

| 方案 | 类型 | 特点 | 适用 |
| --- | --- | --- | --- |
| Chroma | 轻量嵌入式 | 零部署，本地文件 | 原型、小规模 |
| FAISS | 向量索引库 | 性能强，需自管生命周期 | 中等规模，Python 原生 |
| Milvus | 分布式服务 | 大规模、集群、可扩展 | 生产大规模 |
| Qdrant | 独立服务 | Rust 实现，过滤能力好 | 生产 |
| PostgreSQL + pgvector | 关系库扩展 | 与业务数据同库 | 已有 PG 的场景 |

## 关键概念

- **嵌入（Embedding）**：把文本映射为固定维度向量，语义相近 → 向量相近。
- **度量方式**：余弦相似度（常用）、点积、L2 距离。
- **HNSW / IVF**：常见 ANN 索引结构，牺牲少量精度换检索速度。
- **元数据过滤**：先按标签（章节、页码、文档 ID）过滤再向量检索，精度更高。

## 与切分的关系

检索质量 = 切分质量 × 嵌入质量 × 索引质量。切分保证"块内语义完整"，嵌入保证"语义相近
向量相近"，索引保证"百万级也能毫秒返回"。

## 数学检索的注意点

- 公式的嵌入效果通常差于自然语言：符号与自然语言混合会让向量"失真"。
- 对策：公式规范化（LaTeX 标准化）后再嵌入；或对公式区单独建检索通道。
- 元数据过滤很重要：按"章节/教材"过滤比全局向量检索可靠得多。
