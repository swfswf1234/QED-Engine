## 目标与成功标准

### 用户与场景

- **用户**：单用户（图书馆管理员=项目本人），无多用户/权限区分。
- **核心目标**：从零为一门课程建立「教材 + 配套习题集」的 PDF 教材库（≥2 套 approved），供后续解析与学习中心消费。
- **使用节奏**：低频、批量、有等待（探索一轮数分钟、下载以人工登记为主）。设计取向：**等待可观测、中断可恢复、误操作有留痕**。

### 成功标准

用户不读文档也能凭界面提示走完「建领域 → 探索课程 → 采纳 → 确认 → 下载 → 验收」全链路；§验证与验收 的 checklist 全部通过。

## 范围与非目标

- **范围**：下载管理页全部用户操作（领域/课程维护、两类探索、教程与书籍生命周期、筛选浏览）、状态可视化规则、异常降级表现、交互规范。
- **非目标**：解析管理页（单独成文）；控制台/仪表盘；服务端实现细节（见 PLAN-022）；学习中心界面。

## 前置条件

- 探索交互按 PLAN-022 探索会话模型（explore-sessions）设计；课程层探索端点（REQ-065）回执前，课程层探索联调以 mock 先行；
- 前端现状基座：React 19 + AntD + Zustand（ARCH-011 已落地），本计划为交互改造而非推翻重建。

### 2. 端到端主旅程（用户视角）

以「从零建高等数学教材库」为例，8 个里程碑：

```
M1 添加领域        左树底部「➕ 添加领域」→ 填名称 → 树上出现新领域（exploration_stage=未开始）
M2 探索课程体系    右键领域 →「探索课程体系（初始）」→ 选模式 → 等待（进度可见，约 2~4 分钟）
M3 名称确认（可能） 管线建议改名 → 用户裁决保留原名/采纳建议 → 管线继续
M4 应用课程        报告视图勾选课程变更 →「应用所选变更」→ 三态汇总 → 左树长出课程
M5 探索教程        右键课程 →「探索教程」→ 推荐卡（教材+习题集套）→ 勾选（≤4）→ 采纳 → 课程下出现 draft 教程
M6 确认教程      教程行「确认」→ 定稿教材/习题集引用+简介 → 自动生成候选书籍（教材卡+习题集卡）
M7 下载与登记      书籍「决定」→「开始下载」（自动）/「登记下载」（人工 PDF 路径）→ 状态到已下载
M8 验收闭环        「验收」逐册确认 → 全部 verified → 教程 completed → 课程满 ≥2 套 → 探索锁定（完成）
```

每个里程碑可独立中断/返回，进度全部落在数据库（共享表 exploration_stage / qt_* 状态列），**刷新页面不丢失**。

### 3. 用户操作清单（核心规范）

> 锁定/前置条件不满足时，入口禁用并附 Tooltip 说明原因；所有危险操作（删除/否定/过时）必须二次确认；否定/过时必须填原因。

#### 3.2 领域探索（探索课程体系）

> 8900 纯透传不包装异步会话。领域信息卡按钮状态直接反映 exploration_stage。

| 操作 | 入口 | 说明 |
|---|---|---|
| 发起探索 | ① 领域右键 →「探索课程体系（初始/重探）」② 领域信息卡探索按钮（状态机见 §4.2） | **无弹窗直触**：点击后立即发起，进度通过领域信息卡状态+exploration_stage 轮询展示 |
| 选择模式 | 发起前通过领域信息卡下拉或右键菜单子选项选择：`直接开始`（默认）/ `基于整理好的文本探索`（填文本路径，默认提示规范位置 `dataset tmp/exploration` 桶） | 路径须可读文件，否则 400 |
| 等待进度 | 领域信息卡状态更新：exploration_stage 轮询（每 5s）；状态流转：未开始→已生成→探索中→待确认→已完成（5 态，含失败） | 页面刷新后自动恢复轮询；**不依赖弹窗维持状态**，会话由 QED-Tracker 持久化 |
| 名称确认 | 管线建议改名时，领域信息卡切换为待确认状态：原名 vs 建议名 + 理由 | 「保留原名」/「采纳建议名」；确认后管线以该名贯穿重跑 |
| 应用变更 | 报告视图：领域信息卡 + 课程方向 + 课程清单 + 路径图（Mermaid 渲染）；**仅勾选取舍**（默认全选新增项） | 「应用所选变更（N）」→ 三态汇总：已应用 / 跳过（已存在）/ 冲突（拒绝原因） |
| 放弃 | 报告视图「放弃本次」 | 共享表状态回退「未开始」，无任何写入 |
| 失败重试 | 失败状态时信息卡显示「重试」按钮 | 新会话重发同参数；qed_llm_calls 留每次痕迹 |
| 探索历史 | 课程/领域详情（规划项） | 痕迹经「模型调用记录」页（task=domain-explore）可查 |

#### 3.4 教程（教程套）操作

| 操作 | 入口 | 前置状态 | 交互流 | 成功反馈 |
|---|---|---|---|---|
| 确认 | 教程行「确认」按钮 | draft | Modal：教材决定引用·书名 / 习题集决定引用·书名（默认取探索推荐，可修订）+ 简介 | **确认即自动按决定引用生成候选书籍**（2026-08-25 裁决）；toast「教程已确认，书籍候选已按决定引用生成」 |

#### 3.5 书籍操作（8 态按钮矩阵）

| 状态 | 可见按钮 | 说明 |
|---|---|---|
| candidate（候选） | 决定 / 登记下载 / 否定 / 过时 / 详情 | 「登记下载」允许从候选直达（人工已拿到 PDF 的捷径） |
| decided（已决定） | 开始下载 / 否定 / 过时 / 详情 | — |
| downloading（下载中） | 标记失败 / 否定 / 过时 / 详情 | — |
| failed（失败） | 重试 / 否定 / 过时 / 详情 | 显示失败原因 |
| downloaded（已下载） | 验收 / 否定 / 过时 / 详情 | 验收=人工确认版本（书名/语言/版次/完整性） |
| verified（已验收） | 过时 / 详情 | 终态；仅版本换代时可过时 |
| rejected / superseded | （隐藏） | 数据层隐藏，仅留痕 |

**详情弹窗**（任意状态可开）：书籍完整信息 + 否定原因（如有）+ 渠道尝试列表（「查看渠道」加载）+ 登记渠道表单（channel/page_url/download_url/文件关键词）。

**登记下载 Modal**（人工 PDF 链路）：填写相对路径（`dataset/qed-tracker/raw/` 规范桶）→ 8901 校验文件 → downloaded。

#### 3.6 课程状态栏（右面板课程头旁）

> 2026-09-10 新增：课程状态栏与领域信息卡对齐，显示在右面板课程头最右边。

**位置**：右面板课程头（`dl-course-head`）右侧，与课程名称同行。

**状态机**（与领域信息卡 §4.2 对齐）：

| 状态 | 判定 | 按钮表现 |
|---|---|---|
| initial | exploration_stage=未开始 | 主色「开始探索」按钮 |
| running | exploration_stage=探索中 | 置灰「探索中…」（不可编辑） |
| completed | exploration_stage=已完成 | 主色「确认领域信息」按钮（点击打开领域信息确认弹窗） |
| done | exploration_stage=已完成（已确认） | 置灰「探索完成」 |

**交互流**：
1. 未开始 → 点击「开始探索」→ 发起课程探索 → 状态变为「探索中」
2. 探索中 → 等待探索完成 → 状态变为「已完成」
3. 已完成 → 点击「确认领域信息」→ 打开领域信息确认弹窗 → 确认后状态变为「已完成（已确认）」

#### 3.7 领域信息确认弹窗（课程探索完成后）

> 2026-09-10 新增：课程探索完成后，用户点击「确认领域信息」按钮打开此弹窗。

**弹窗内容**：
1. **课程信息区**：课程名称（不可编辑）、课程描述（不可编辑）
2. **教程详情表格**：
   - 教程名称（可编辑，`PATCH /api/v1/knowledge/{id}`）
   - position 定位（可编辑，下拉选择：基础/进阶/综合/专题）
   - 详情按钮（点击查看 intro 描述，可编辑）
   - 教材、习题集、其他资料（不可编辑，来自探索推荐）
   - 否定按钮（删除该教程，`DELETE /api/v1/knowledge/{id}`）
3. **操作按钮**：关闭（取消）、确认（进入已完成阶段）

**前置条件**：
- 课程 exploration_stage=已完成（已生成探索结果）
- 8901 在线（需要调用 knowledge 相关 API）

**交互流**：
1. 用户点击「确认领域信息」→ 打开弹窗
2. 加载课程详情（`GET /api/v1/courses/{course_id}`）和教程列表（`GET /api/v1/knowledge?course_id={course_id}`）
3. 用户编辑教程名称、position、intro
4. 用户可删除不需要的教程（否定按钮）
5. 点击「确认」→ 调用 `POST /api/v1/courses/{course_id}/confirm` → 课程状态变为「已完成」

**后端依赖**（需 8901 新增）：
- `PATCH /api/v1/knowledge/{id}`：更新教程（name、position、intro）
- `DELETE /api/v1/knowledge/{id}`：删除教程

### 4. 状态可视化规则

#### 4.1 徽标与色点

| 元素 | 规则 |
|---|---|
| 书籍状态徽标 | candidate 默认灰 / decided 蓝 / downloading 橙 / failed 红 / downloaded 青 / verified 绿 |
| 课程探索色点 | 未探索灰 / 探索不足黄（exploration_stage=已生成或探索中）/ 已达上限绿（已完成） |
| 教程进度文案 | 套数 x/2 · 教材 a/b · 习题集 c/d（b/d 动态计算） |
| 版本徽标 | 中译本 / 英文版 / 苏版 / 其他（由 language+书名推导；苏版名单常量） |

#### 4.2 领域信息卡探索按钮状态机（5 态）

| 状态 | 判定 | 按钮表现 |
|---|---|---|
| running | exploration_stage=探索中 | 置灰「探索进行中…」 |
| initial | exploration_stage=未开始 | 主色「探索课程体系（初始）」 |
| pending | exploration_stage=待确认 | ghost 主色「探索课程体系（待确认）」 |
| completed | exploration_stage=已完成 | ghost「探索课程体系（已完成）」+ Tooltip「可再次发起重探」 |
| failed | exploration_stage=失败 | danger「探索失败」+ Tooltip 显示 explore_pending.error 中的失败原因；ghost「重试」按钮 |

> 改造说明（REQ-064 后 + REQ-067 统一）：判定数据源从「knowledge 完成度实时推断」
> 切换为「共享表 exploration_stage 直读」；状态机从 4 态扩展为 5 态（+失败），
> 探索执行由 QED-Tracker（8901）驱动，8900 纯透传。

#### 4.3 课程状态栏探索按钮状态机（4 态）

> 2026-09-10 新增：与领域信息卡状态机对齐，用于右面板课程头旁的状态栏。

### 5. 异常与降级流

| 场景 | 用户可见行为 | 数据安全 |
|---|---|---|
| 8900 不可达 | 页面顶部整体错误横幅 + 重试按钮 | — |
| 课程体系不可达（共享表读失败） | 树区空态「课程体系数据不可达（8900/8901 未启动或离线）」 | — |
| 教程不可达（8901 离线） | 警告横幅「教程数据不可达，8901 离线时展示降级，不阻塞树目录」；树/课程维护/领域探索**仍可用**（降级模式）；教程确认/书籍操作禁用 | 共享表维护写入暂存，恢复正常 |
| 8901 在线但数据库 409 | 透传提示「数据库未配置」 | — |
| 探索管线失败（LLM 超时/预算耗尽） | 弹窗失败视图 + 错误信息 + 重试按钮；qed_llm_calls 留 error 痕迹 | 已产生步数的 LLM 记录保留 |
| 名称确认中断 | 会话挂起 waiting_name_confirm，弹窗重开可继续裁决 | 无写入 |
| 应用冲突 | 三态汇总列出冲突项与拒绝原因；已应用项不回滚 | 部分应用允许 |
| 页面刷新/关闭弹窗 | 轮询中断后自动恢复；未终态会话重进页面续轮询 | 会话由 QED-Tracker（8901）持久化，无 TTL 清理 |
| mock 模式 | 弹窗顶部黄条「探索 Mock 模式已开启」；真实 8901 不被调用 | 刷新即消失 |
| 课程状态栏探索失败 | 课程探索失败时，状态栏显示「重试」按钮（danger 样式）；tooltip 显示失败原因 | 探索失败不影响现有教程数据 |
| 领域信息确认弹窗加载失败 | 弹窗显示错误信息 + 重试按钮；8901 离线时禁用确认按钮并提示 | 无写入 |
| 教程删除失败 | toast 显示服务端错误详情；教程行保持不变 | 无写入 |

### 6. 交互规范

1. **危险操作**：删除领域/课程、教程否定/过时、书籍否定/过时 → 一律二次确认 Modal；否定/过时原因必填。
2. **长任务**：探索一律走「发起 → 轮询 → 结果」弹窗流；轮询间隔 3~5s；**绝不使用同步长请求**。
3. **可恢复性**：关闭弹窗不打断会话；同目标重开直达现场；刷新页面后未终态会话自动续轮询。
4. **原子反馈**：每个写操作成功/失败都有 toast；失败文案透出服务端 detail（错误码语义化）。
5. **乐观更新禁用**：树与书籍列表一律以服务端返回为准（操作后 refreshDetail / fetchAll），不做本地乐观变更，避免状态机漂移。
6. **表单默认值**：探索推荐（教材/习题集名）预填可修订；登记下载路径预填规范桶提示。
7. **数据一致性**：rejected/superseded 行由数据层统一隐藏；进度文案（x/2、a/b、c/d）动态计算不缓存。
8. **课程状态栏**：与领域信息卡样式一致，按钮状态根据 `exploration_stage` 实时更新；探索中状态不可编辑。
9. **领域信息确认弹窗**：课程信息不可编辑，教程详情可编辑；否定按钮直接删除教程（非 rejected 留痕）；确认后课程状态变为「已完成」。
10. **统一课程编辑弹窗**：两个入口（左树右键、右面板详情按钮）调用同一个弹窗组件；字段精简为：课程描述、学习阶段、学术方向、别名、依赖课程。
