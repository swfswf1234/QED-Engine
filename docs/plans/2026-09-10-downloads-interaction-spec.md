## 1. 课程详情弹窗（原 PLAN-035）

### 1.1 弹窗行为

- **打开即编辑表单**：无查看/编辑模式切换，弹窗始终显示编辑表单
- **操作按钮不在弹窗内**：探索/确认/完成等操作由 `CourseStatusBar`（课程头右侧按钮）处理
- **弹窗内字段**：课程名（只读）、课程描述、学习阶段、学术方向、别名、依赖课程
- **保存逻辑**：调用 `updateCourse()` PATCH API，成功后 `fetchAll()` 刷新数据

### 1.2 课程状态栏 5 态状态机

`CourseStatusBar` 组件根据 `course.exploration_stage` 显示不同按钮：

| 状态 | 按钮文案 | 按钮类型 | 可点击 | 行为 |
|------|---------|---------|--------|------|
| 未开始 | 开始探索 | primary | ✅ | 调用 `exploreCourseKnowledge()` |
| 探索中 | 探索中… | default（loading） | ❌ | 禁用 |
| 待确认 | 确认领域信息 | primary | ✅ | 调用 `confirmCourse()` |
| 已完成 | 探索完成 | default | ❌ | 禁用 |
| 失败 | 重试探索 | primary danger | ✅ | 调用 `exploreCourseKnowledge()` |

### 1.3 状态流转图

```
┌─────────┐    用户点击     ┌─────────┐   探索完成    ┌─────────┐
│  未开始  │ ─────────────→ │  探索中  │ ───────────→ │  待确认  │
└─────────┘                └─────────┘              └─────────┘
                                │                        │
                                │ 失败                   │ 用户确认
                                ↓                        ↓
                           ┌─────────┐             ┌─────────┐
                           │   失败   │             │  已完成  │
                           └─────────┘             └─────────┘
                                │
                                │ 重试
                                ↓
                           ┌─────────┐
                           │  未开始  │
                           └─────────┘
```

## 2. 书目详情操作（原 PLAN-036）

### 2.1 弹窗行为

- **信息展示 + 书目操作集**：弹窗显示教程信息和书目列表
- **移除底部按钮**：无"关闭""确认下载"按钮，仅保留右上角 X 关闭
- **渠道列表**：显示书目的所有渠道尝试（来源、状态、下载链接）

### 2.2 三条操作链路

#### 链路 A：验证完毕
- **触发条件**：渠道状态为 `downloaded`
- **操作**：调用 `verifyBook(bookId)` → 状态变为 `verified`
- **UI 反馈**：成功 Tag + 按钮消失

#### 链路 B：否定
- **触发条件**：任意渠道状态
- **操作**：弹出原因弹窗（原因必填、备注可选）→ 调用 `rejectBook(bookId, reason)` → 状态变为 `rejected`
- **UI 反馈**：失败 Tag + 失败原因红色展示

#### 链路 C：手动导入
- **触发条件**：无可用渠道或渠道全部失败
- **操作**：文件选择器选取本地 PDF → 调用 `importBookPdf(bookId, file)` → 刷新渠道列表
- **UI 反馈**：新增渠道项 + 导入成功提示

### 2.3 渠道状态展示

| 渠道状态 | Tag 颜色 | 附加信息 |
|---------|---------|---------|
| downloaded | 绿色 | 可验证/否定 |
| verified | 蓝色 | 已确认 |
| failed | 红色 | 显示失败原因（note 字段） |
| rejected | 灰色 | 已否决 |

## 3. 统一交互规范

### 3.1 §6.5 乐观更新禁令

**规定**：所有操作后必须调用 `fetchAll()` 从服务端获取最新状态，禁止前端直接修改 store 中的状态值。

**原因**：后端状态写入可能失败（DB 连接、状态机冲突等），乐观更新会导致 UI 状态与实际不一致。

**示例**：
```typescript
// ✅ 正确：操作后 fetchAll
await exploreCourseKnowledge(courseId);
await fetchAll();

// ❌ 错误：乐观更新
setCourseStage(courseId, '探索中'); // 禁止
```

### 3.2 与 DomainCard 状态机一致性

课程状态栏的 5 态状态机与 DomainCard 的领域状态机保持一致：

| 状态 | DomainCard 按钮 | CourseStatusBar 按钮 |
|------|----------------|---------------------|
| 未开始 | 开始探索 | 开始探索 |
| 已生成 | 领域信息确认 | —（课程无此状态） |
| 探索中 | 探索中 | 探索中… |
| 待确认 | 课程知识确认 | 确认领域信息 |
| 已完成 | 探索完成 | 探索完成 |
| 失败 | 重试探索 | 重试探索 |

### 3.3 弹窗关闭策略

- **课程详情弹窗**：保存成功后自动关闭；取消时直接关闭（无确认提示）
- **书目详情弹窗**：操作（验证/否定/导入）后不自动关闭；仅 X 按钮关闭
- **领域确认弹窗**：确认后自动关闭 + `fetchAll()` 刷新

### 3.4 课程头布局

- **布局方式**：`.dl-course-head-row` 使用 `display: flex; justify-content: space-between`
- **与 DomainCard 对齐**：名称左 + 操作按钮右，与 `.dl-domain-card-header` 一致
- **课程描述**：`.dl-course-head-note`，font-size: 14px，与 `.dl-domain-card-info p` 统一
