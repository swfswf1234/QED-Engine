## 目标与成功标准

为后台管理侧新模块「文档分析处理」持一份**前端可见视角的设计稿**：它是全流程 ③（解析之后、学习中心消费之前）的内容加工桥接，把解析产物提炼为可学习成品。根侧只持设计稿 + 登记跨项目移交，**后续具体细节由 Axiom-Flow 负责**；路由 / 命名等待用户确认后晋升进 `design/frontend/`。

成功标准正本在 todo REQ-116 行 S1~S4（写定不改）。

## 范围与非目标

**范围（根侧）**：① 前端可见视角的模块设计稿（定位 / 四职责 / 输入输出 / 边界 / 展示）；② 用户确认路由与命名（已定稿）；③ 向 Axiom-Flow 移交后续细节（分析算法、后端端点、目录与知识点两表写入、习题讲解来源）；④ 确认后晋升 `design/frontend/doc-analysis.md`。

## 设计本体（前端可见视角，待晋升）

### 定位

文档解析（[parsing-ui.md](../design/frontend/parsing-ui.md) / [parsing-flow.md](../design/parsing-flow.md)）产出的是**版面 / 块级内容**（页图、语义 bbox、blocks 文本 / 公式 / 图像），尚不是「可学习的成品」。文档分析处理负责把块级内容提炼为**语义成品**交学习中心消费——是后台管理侧的最后一道加工，**纯管理侧、不辅助学习本身**。

### 四职责（确定）

1. **生成 / 人工修正课本目录**：由解析产物生成课本目录并支持人工修正，成品供学习面「章 ＋ 知识点」两级阅读推进直读。两条腿由 [REQ-117](../history/plans/2026-10/2026-10-15-learn-course-study-redesign.md) 裁决 C2／V2.2 移交本模块——学习面「修改目录」入口（人工通路）已摘除，进面自动生成只属**本模块承接前的过渡通路**。
2. **登记 / 确认知识点**：从解析内容识别候选知识点，经人工确认（确认／驳回）后登记（喂学习中心·知识探索 / 课程学习）。**确认／驳回的唯一写面在此屏**——学习面维持零确认写面（REQ-117 C1／C14／B6／C25~C28）。
3. **展示 / 编排课本学习链路**：为一本课本编排合适的学习链路（章节单元 → 知识点序列的推进顺序），供课程学习按链路推进。
4. **关联课后习题及讲解**：把对应课后习题及其讲解关联到知识点 / 章节（喂学习中心·课后练习）。

### 驱动方式（用户裁决 2026-10-15）

**LLM 自动分析 + 人工确认**：知识点识别与学习链路编排由 LLM 自动产出候选，人工确认后才登记为成品（不做纯自动、也不做纯人工）。是否走 8900 `/llm/*` 网关、提示词与评分口径等**具体细节由 Axiom-Flow 负责**。

### 输入 / 输出

| 方向 | 内容 | 来源 / 去处 |
| --- | --- | --- |
| 输入 | 已激活解析版本的 blocks / pages（版面 + 块级文本 / 公式 / 图像） | 解析产物（af_*，结构唯一事实源在 Axiom-Flow） |
| 输出① | 已确认课本目录（章 → 知识点两级） | 学习中心·课程学习左栏 |
| 输出② | 已确认知识点 | 学习中心·知识探索 / 课程学习 |
| 输出③ | 课本学习链路（章节单元 ↔ 知识点序列编排） | 学习中心·课程学习 |
| 输出④ | 课后习题 + 讲解关联 | 学习中心·课后练习 |

### 边界（与相邻模块不重叠，确定）

- **与文档解析管理（parsing-ui）不重叠**：解析管理做**块 / bbox 级**修正与判定（版面真伪、文字正确性）；文档分析处理做**语义级**知识点抽取、链路编排、习题关联（内容含义与学习组织）。前者管「解析对不对」，后者管「怎么变成可学的」。
- **与学习中心不重叠**：本模块只**生产**成品，不承载面向学习者的引导 / 作答交互；学习中心只**消费**成品。
- **学习面过程性内容不得回流**（2026-10-18 随 [REQ-117 §V2.6／C23](../history/plans/2026-10/2026-10-15-learn-course-study-redesign.md) intake）：「整理中／整理失败／无可读教材／章内零知识点」四类处理情况说明只在本模块与解析管理呈现，学习面目录一律不显示；目录未就绪与知识点缺位的**生产与运维**归本屏，学习面只给消费侧降级话术。
- **学习者备注不作提升来源**（2026-10-17 由 [REQ-117 壳 §V2.12／C26](../history/plans/2026-10/2026-10-15-learn-course-study-redesign.md) 随步增补）：候选池 `qe_learn_kp_detail` 里 `payload.kind='note'`／`gen_batch='learn-note'` 的行＝学习面「备注」段的学习者自记内容（`gen_status=draft`），只供学习者回看；**本模块的确认队列不得把它们列为知识点提升候选**——服务端 `confirm_detail` 只拒 `rejected`（draft 亦可提升），隔离靠本边界＋确认队列按 `gen_status=candidate` 过滤，契约口径见 [api-contracts.md](../architecture/api-contracts.md) 的 `POST /learn/kp-details` 行。
- **跨项目归属**：根侧持前端可见设计稿；分析算法、后端端点、知识点两表写入、习题讲解来源等**后续细节由 Axiom-Flow 负责**（按其仓库门禁与 ADR）。

### 前端展示（路由与命名已定·形态待细化）

**路由＝`#/admin/analysis`，模块中文名＝文档分析处理**（用户裁决 2026-10-18），位置＝后台管理侧全流程 ③ 屏，与文档解析管理 `#/admin/parsing` 并列。形态待细化。初步设想（**非定稿**）：分析任务列表（按书目列状态：未分析 / 分析中 / 待确认 / 已确认）+ 单书分析工作区（目录生成与人工修正；知识点候选 → 人工确认入库；学习链路编排；习题关联）。复用后台管理通用组件与 theme token，不新造视觉。
