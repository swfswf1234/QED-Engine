## 机制（捕获 → 审核 → 批量晋升 → 体系优化）

1. **捕获**：一个大任务完成后，将该任务中对 agent 的利用情况与有价值信息写入本文档
   条目区（也可随时手动要求补充）；写入前过一遍审核判据。
2. **审核三判据**（逐条过，任一不满足不入池）：
   - **复用价值**：未来任务还会遇到（非一次性巧合）；
   - **非瞬时状态**：不是「某服务此刻离线」等临时现象；
   - **未被覆盖**：现有正式文档没有该知识。
3. **批量晋升触发**（三者先到即触发一次分析优化轮）：
   - 待评审条目 ≥10 条；
   - 单一主题聚集 ≥3 条（如环境类/命令类/联调类/文档缺口类）；
   - 每月例行梳理（无论条数）。
4. **体系优化**：分析轮对条目聚类，产出结构性结论（哪类知识反复探索 = 文档体系哪里
   有洞），按结论修订正式文档乃至开发流程本身；完成后清空已晋升条目并在文末登记。

### [2026-08-26] REQ-061 qwen3.8 系推理模型在结构化长生成上病态慢
- 场景：LLM 网关修复真实验证——同一 courses@v3 探索 prompt 跨模型对比。
- 反复探索点：任务卡超时上限时，先入为主怀疑网关/prompt 构造；实际需跨模型对照才能定性。
- 解法：实证数据——qwen-plus 完成同任务稳定 42~56s（历史 5 例）；qwen3.8-2.4t-a95b >600s、
  qwen3.8-max >300s/>600s/>1200s 均未完成；小输出任务（domain 步骤）qwen3.8-max 仅 62s。
  **2026-08-26 补充**：qwen3.7-plus 三步全链路通过（domain 49.6s / courses 107.0s·13 门 /
  path 58.1s，call 88~90），可用作探索管线模型（较 qwen-plus 慢约一倍但在默认 300s 内宽裕）。
  结论：思考型大参数模型在长结构化 JSON 生成上推理延迟病态，探索类管线应选快速模型
  或为推理型模型单独放宽 QED_LLM_TIMEOUT。另注意：客户端中断请求后服务端仍会跑完落库，
  /llm/calls 可回收「被中断」请求的最终结果（call 83 即此法所得）。
- 建议归类：联调（可考虑向 QED-Tracker 提示模型选型；流式/enable_thinking 支持为网关远期方向）
- 状态：待评审

### [2026-08-26] REQ-061 pydantic-settings env_file 相对 CWD 是启动方式歧义源
- 场景：8900 真实验证准备——手动 `cd backend` 启动后 keys.configured=False、数据库不可达。
- 反复探索点：`SettingsConfigDict(env_file=".env")` 相对 CWD 解析；脚本启动（cwd=仓库根）
  与手动启动（cwd=backend/）读到不同配置，排查需先意识到「配置随 CWD 漂移」这一可能。
- 解法：env_file 绝对定位仓库根（`Path(__file__).resolve().parents[2] / ".env"`），
  已在根仓库实施并修订 configuration-and-secrets.md（2026-08-26 根 .env 唯一事实源裁决）。
- 建议归类：环境（已修复，本条留档作模式警示：任何相对路径资源加载都要先问 CWD 是谁）
- 状态：待评审

### [2026-08-26] REQ-061 后端改码后必须重启 8900 才加载新配置
- 场景：LLM 网关缺陷修复（QED_LLM_TIMEOUT 新增）的真实验证准备。
- 反复探索点：改完 backend 代码后直接验证发现行为未变——uvicorn 默认无 `--reload`，
  常驻的 8900 旧进程仍跑旧代码；需先重启再验证（前台 Ctrl+C 或 `POST /self-restart`，
  或后台 Start-Process 方式重新拉起）。
- 解法：凡根仓库 backend 代码/配置改动后的真实验证，第一步固定为重启 8900 并以
  `GET /api/v1/health` 确认新进程存活。
- 建议归类：流程（可考虑固化进 operations.md「重启与诊断」节一句话强调）
- 状态：待评审
