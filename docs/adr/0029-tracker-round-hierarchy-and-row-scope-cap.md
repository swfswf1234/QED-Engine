# ADR 0029：台账分层与轮节瘦身（备注下移、总任务上轮、行只写范围）

状态：Accepted
日期：2026-11-03
领域：工程治理
决策阶段：v0.1
取代：—
被取代：—

## 背景

用户 2026-11-03 就任务台账下三条令（原文「1、首先备注要在轮下面；2、学习设计轮只写主任务和每个
需要改的模块的总任务，其他都归普通任务轮；3、每个任务都需要一个对应的plans/文档，细节和过程写入
plans/文档，要清理一下任务重叠的要合并……可以破坏性重组避免过多任务导致的混乱」），并点名
「是不是细节都写任务中了」。

对 [docs/trackers/todo.md](../trackers/todo.md) 改前的机械量测坐实了这三条不是观感问题：

| 症状 | 改前读数 |
| --- | --- |
| 轮节标题承载叙述 | 「学习设计轮」标题行约 300 字符，内嵌四段收口顺序、批次归属与裁决沿革 |
| 主线轮节行数 | 学习设计轮 11 行＝1 枚主线＋10 枚支线，其中四段中三段（梳理、融合、习题、确认位）互为同一模块的重叠工作 |
| 任务描述列承载过程 | 14 行超 500 字符，最长 REQ-143 达 **6531 字符**——十道令的裁值、代价、逐批落地与门禁数字全写在行里 |
| 其余肥行 | DEFECT-026 1286／DEFECT-027 946／REQ-141 869／DEFECT-025 803 字符（取证三段、文件行号、改判日期都在行内） |

ADR 0023 把「证据/下一条件」列退役、把过程赶到壳里，但**没有管「任务描述」列**，于是过程叙述换了
一列继续长大：行读不动、模块之间的重叠看不出、todo 与 `plans/` 的事实源分工被反向侵蚀（行里的事
实在壳里没有第二份，行一删就丢）。这正是 ADR 0023 背景节所说「行变成过程草稿纸」的残余形态。

## 决定

| ID | 决定 | 理由 | 守护 |
| --- | --- | --- | --- |
| L1 | **轮节三段式**：每个任务节依次为 `### 轮名` → 节下备注段 → 表格。标题行只写轮名，长度 ≤64 字符且不得出现 `——` 与 `；`；轮次定位、批次沿革、收口顺序、裁决出处一律写进节下备注段（ADR 0023「过程与证据落壳」在台账侧的同构延伸）。备注段必须落在标题与表头之间，不得插进表格区 | 标题是导航面，承载叙述后一屏读不出「这个节是什么轮」 | G8a |
| L2 | **主线轮节分层**：含 `类别=主线` 行的节，其节下备注必须声明形态之一——粗体字面标记 `**分层轮**`（只登记该主线行与各模块的**总任务行**，其余工作一律挪到默认承载轮）或 `**承载轮**`（默认承载轮专用，全台账至多一节声明它）；正文里普通提到「默认承载轮」不构成声明。声明 `**分层轮**` 的节，其非主线行的任务描述必须含 `总任务` 三字且该节总行数 ≤8 | 「一个轮＝一个模块的总览」是可检查的；不声明就不允许有支线行挂在主线节里；字面标记避免「备注里叙述性提到另一种形态」被误判成声明 | G8b |
| L3 | **模块总任务行的承载**：每枚总任务行原则上整格链接**自己的一枚 `plans/` 壳**（ADR 0016 一任务一行一壳）；同一滚动壳分线承载多枚总任务时（判例 ARCH-025-L1／L2／L3），行内链接该壳并在壳的分线登记表各留一条目，不得多行整格链同一壳（镜像守护会判双写） | 用户令 3「每个任务都需要一个对应的 plans/文档」；细节与过程只有壳这一个落点 | G8d |
| L4 | **任务描述列 ≤500 字符**，只写「做什么 + 目标/效果 + 文档锚」。现网取证数字、文件行号、令文与裁值沿革、代价登记、工作项拆解、逐批门禁输出**不得**写在行内，落承载壳的「过程与证据」或专门节 | 行是索引不是正文；两处正文即漂移（ADR 0023「目的与边界」收敛判据的推广） | G8c |
| L5 | **先回填后瘦身**：删行内叙述前必须逐行核对承载壳是否已有该事实，缺失先补进壳（带 `YYYY-MM-DD` 日期戳）再删。壳不删（ADR 0021 归并不删壳）；挪节、升格为总任务、降格并入普通任务轮都是**归属改动**，须用户裁决（ADR 0022 决定 5），agent 不得自行改判 | 瘦身是移动信息不是销毁信息；行里的取证与裁决多是当前唯一副本 | 人工自查（`qed-closeout`） |
| L6 | **成功标准列一字不动**：本轮重组只改「任务描述」列与行的归属节。S 判据的冻结义务（ADR 0022 决定 4／ADR 0023 决定 2）不被本轮削弱；判据需要扩写时另登新行，不借重组改写既有行 | 借「整理台账」之名改判据＝改范围，是本决定最容易被滥用的缝 | G2（既有） |
| L7 | **重叠工作的合并出口＝挪节＋回指，不是并判据**：同一模块的多行重叠工作（判例：梳理段的 REQ-141／143／148／149／150）由一枚总任务行在节内统领、细则行落默认承载轮的 `####` 模块子分组，各行的 S 判据与壳保持独立；确需合并为一个任务时按 ADR 0023 走「用户裁决改范围」，不在本轮做 | 用户令的是「避免过多任务导致的混乱」＝排列问题，删除任务会连带删判据与证据 | G8b |

## 后果

- 一次性迁移（本轮做完）：学习设计轮节 11 行 → 5 行（1 主线＋4 模块总任务），其余 7 行挪入默认
  承载轮并加 `####` 模块子分组；14 枚肥行逐行回填壳后瘦到 ≤500 字符；6 个节标题瘦身＋备注下移；
  新登一枚知识点梳理模块总任务行与其壳（既有各段行都不承担「模块总览」的形态，无法就地升格）。
- 台账一屏读得出形状：主线轮＝该模块要改哪几块，默认承载轮＝在做的细则清单，长期任务＝滚动复核面。
- 代价与风险：≤500 字符是**形式上限，不保证内容搬全**——真正的防线是 L5 的逐行回填核对，跳过去
  就会丢事实；G8c 判红只说明「这行该读壳了」，不说明壳里已有那份正文。
- `**分层轮**`／`**承载轮**` 声明是节下备注里的字面粗体标记，改标准正文而不改声明不会自动红；因此 G8b
  同时断言「含主线行的节必须二选一声明」，漏声明即红，把声明本身变成必需件而不是可选注释。判定只认
  粗体标记，故备注里叙述性提到另一形态不会造成双重声明。
- 不取代任何现行 ADR：本决定是对 [ADR 0016](0016-todo-registration-one-task-one-plan.md)（行的薄登记
  形态补「行只写范围」一侧）、[ADR 0020](0020-task-closure-cadence-and-thin-registration.md) 与
  [ADR 0021](0021-round-proliferation-cap-and-per-row-doc-anchor.md)（节与承载的层级结构）、
  [ADR 0023](0023-todo-row-carries-scope-and-criteria.md)（过程叙述的残余落点）的**结构收紧**。
