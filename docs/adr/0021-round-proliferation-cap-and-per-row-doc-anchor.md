# ADR 0021：轮次不增设与 todo 行文档锚（关闭轮不留节，一行一锚）

状态：Accepted
日期：2026-09-30
领域：工程治理
决策阶段：v0.1
取代：—
被取代：—

## 背景

[ADR 0016](0016-todo-registration-one-task-one-plan.md) 规定「一任务一行一壳」与新增轮次须用户确认，
[ADR 0020](0020-task-closure-cadence-and-thin-registration.md) 补上收口节拍与薄登记上限（G1~G4）。
2026-09-30 用户复核台账时发现两条 0020 未覆盖的漂移，且都属于「规则有、防线无」：

- **已关闭轮次残留节**：存储链路规范化轮（ARCH-032）已于 2026-09-26 关闭并把壳 Retain 归档
  `history/plans/2026-09/`，但 todo 仍保留「存储链路规范化轮（ARCH-032）」整节，其下 REQ-091 /
  REQ-092 / REQ-096 三行挂在一个已经不存在的轮名上；接手者按节名找不到壳，也无从判断这三行归谁排期。
- **行没有事实源去处**：同一批三行连同 REQ-006、REQ-031、OPS-001、DEFECT-007、REQ-050 共 **8 行**
  「任务」列不含任何文档链接（G5 先红实录），其边界、勘察证据与修向全部写在 todo 单元格内。
  ADR 0020 的 G2 只限制证据列长度，**不要求给出过程叙述的落点**，于是「不许写长」反而促成
  「写在 todo 里但写短」——内容仍然错置。
- **轮次只增不减**：2026-09-24 立 ARCH-032、2026-09-29 同日立 ARCH-035（普通任务轮）与 ARCH-036
  （运行时产物与备份面轮），三者实为同一族「规范化与零散收口」工作。每族工作各起一个主线轮节，
  正是用户指认的「乱」：主线轮名义上都是「有终态的大目标」，实际承载的是可随到随登的条目。

同时，`test_tracker_governance.py::test_todo_plan_rows_exactly_mirror_active_plan_bodies` 要求
`docs/plans/` 下每个壳被**恰好一行**以「整格＝plans 链接」形式镜像（状态须等于壳状态）。这条既有
不变量决定了：多行不能共用一个镜像链接，归并轮次不能靠删除壳的镜像行来实现。

## 决定

1. **轮次非必要不增设（承载优先）**：新增工作默认落 `普通任务轮`（ARCH-035）壳的登记表条目，或既有
   长期线；只有**需要独立设计评审、或范围跨模块需独立边界**的工作才立轮，立轮仍须用户确认（0016）。
   同一族的规范化/零散收口工作不各自立主线轮。
2. **关闭轮不留节**：轮次关闭（壳转终态并归档）时，其 todo 节必须同批撤销；节下残留的未关闭条目
   按第 1 条并入 `普通任务轮` 或 `长期任务` 节，不得挂在已归档轮名下。
   守护：`test_tracker_governance.py::test_todo_section_headings_point_at_live_rounds_or_generic_sections`（G6）。
3. **一行一文档锚**：todo 每行「任务」列必须含至少一个指向仓库内真实文件的 Markdown 链接——承载它
   的 `plans/` 壳、其他事实源文档（`standards/`、`design/`、`architecture/`、`guides/`）或台账文档。
   无链接即红；链接目标不存在亦红。守护：
   `test_tracker_governance.py::test_todo_task_rows_carry_a_document_anchor`（G5）。
4. **锚与镜像的分工**（不破坏既有不变量）：一个壳仍只由一行镜像（整格＝plans 链接）；其余条目行用
   **行内链接**取锚，行内链接不参与镜像校验。因此「多条目共一承载壳」的合法形态＝承载壳的镜像行
   一条 + 各条目行的行内链接，而非多行同时冒充镜像行。
5. **归并不删壳**：某轮被判定归入普通任务轮、而其壳仍需继续承载执行与取证时，**保留该壳文件与其镜像
   行**，把该行的 `类别` 由 `主线` 降为 `支线` 并移入 `普通任务轮` 节；承载壳内只登记一条「承载关系」
   条目并指向该壳，不复制其工作项正文。删除活跃轮的唯一合法路径仍是关闭 + 归档判定（Retain/Delete）。
6. **同步义务与首批判例整改**（2026-09-30 用户三裁决）：修订 [task-lifecycle.md](../standards/task-lifecycle.md)
   「收口节拍、薄登记上限与承载归属」表与守则；台账整改＝ARCH-032 节撤销、REQ-091/092/096 并入普通任务轮并补锚，
   ARCH-036 按第 5 条降级并入（其壳保留执行面），OPS-001 / REQ-031 入普通任务轮待开始条目，REQ-050 补
   文档治理锚，DEFECT-007 改行内锚；REQ-006 按 ADR 0020 达成即收关闭（管理后台已落地＝达成项，
   学习界面移交 ARCH-027-M1 壳），整行移入 completed.md。

## 后果

- todo 每一行都能一跳到达其事实源；「只有 todo 知道的事」不再存在。G2（长度上限）与 G5（必须有锚）
  组成闭环：G2 说「不许把过程写这儿」，G5 说「那必须写明写在哪」。
- 轮次数量收敛：普通任务轮成为默认承载轮；再出现「某族工作要不要立轮」的判断时，答案是除非需要
  独立设计评审，否则不立。已立轮次若被关闭，节与行不再滞留（G6 拦截）。
- ARCH-036 形态说明：它不再以「主线轮节」出现在台账，但其壳与镜像行保留，执行与取证仍在原壳内——
  归并改的是**归属表达**，不是执行记录，避免打断并行窗口正在跑的工作项。
- G6 的判据是「分节标题出现的任务 ID 必须是台账活跃行」，因此节名可以写轮名（可读性优先），代价是
  轮关闭时必须同批改节名，不能只删行。
- 不取代 0016 与 0020：一任务一行一壳、薄登记、收口节拍全部保留；本 ADR 只补「承载归属」与
  「文档锚」两维，属 [ADR 治理](../standards/adr-governance.md) 意义上的**部分补充**（正文关联，
  0016 / 0020 状态与决定不变）。
