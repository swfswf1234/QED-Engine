# ADR 0024：1.0 前 schema 重建档位与 demo 门（范围锁死）

状态：Accepted
日期：2026-10-14
领域：工程治理
决策阶段：v0.1
取代：—
被取代：—

本决定**补充** [ADR 0019](0019-runtime-artifact-placement-and-no-long-term-backups.md) 决定 4
（备份只为回滚窗口存在、验收即清）在 schema 演进场景的档位划分，不取代其任何决定；
与 [ADR 0023](0023-todo-row-carries-scope-and-criteria.md)（判据正本在行）配合使用。

## 背景

2026-10-14 用户提出三条开发流程优化：① 表结构在 1.0 前未稳固，希望豁免「备份 → ALTER →
模型同步 → ensure_schema (0,0)」四步窗口（该窗口正文在 QED-Tracker
`qed-db-alter-redline-window` 技能与 `database-private-tables.md`，其存在理由是
`ensure_schema` 对私有表列集漂移执行 DROP+CREATE，勘查即清库）；② 大任务应先做核心功能
demo 交人类验证再扩展，且实现不得超出 docs/ 设计文档；③ 开发尽量遵循第一性原理把握核心。

评估修正（agent 提案、用户同日拍板）：

- ① 的判据不用版本号——版本号与数据价值无关（反例：`af_books` 的 b05 全本解析产物是数小时
  GPU 成果，1.0 前也丢不起；`qed_test` 库表随手可重建）。判据改**数据可再生性**分档。
- ③ 不独立成条——「把握核心」写不出机械守护判据，入标准即空文；其可执行化身＝②的 demo 门
  （demo 的本质＝「该任务核心价值的最短验证路径是什么」）与既有「一句话成功标准，写不出则
  不成为行」（task-lifecycle）。

## 决定

1. **1.0 前 schema 演进档位**（适用窗口：项目宣布 1.0 之前；宣布后另立 ADR 收口本条）：
   - **自由重建档**：数据可自动或低成本再生——测试库（`qed_test` 等）、纯日志账目表
     （LLM 调用账 `qed_llm_calls` 等，用户裁决 2026-10-14 明确免备份）。schema 变更直接改
     模型 → DROP+CREATE 重建（或 `ensure_schema` 自愈），**免四步 ALTER 窗口、免备份**。
   - **备份确认档**：再生昂贵的数据——解析产物登记（`af_*`）、下载原件与登记（`qt_*` 中
     指向不可重得文件的行）等。免四步 ALTER 仪式，但**临时备份 → 用户确认 → 重建**三步
     不可免。备份遵守 ADR 0019 决定 4：只为本次操作回滚窗口存在，落点
     `dataset/backups/YYYY-MM-DD-<任务标识>`，**验收确认后全部清理完毕、不留残留**
     （用户裁决原文：「备份要固定删，完成之后确认后要全部清理完毕不要残留」），留痕靠
     completed.md 与壳的「过程与证据」节。
   - **生产库红线不豁免**：生产 `qed` 库任何档位都不适用本条（REQ-093 既有裁决、
     db-alter 技能第 7 步口径不变）。
   - 档位归属判据写进 [database-design.md](../architecture/database-design.md)「迁移」节
     （唯一事实源）；各仓库技能与私有表文档只放指针，不复制档位表。
2. **demo 门（一壳一门）**：大任务（多工作项 B 类壳）的第一个工作项必须是「核心场景端到端
   最小可跑」demo——一条黄金路径、真数据、真环境（前端即真浏览器验证），以**核心价值最短
   验证路径**界定范围（第一性原理的落点）；到门暂停待人工验收，验收通过才进扩展批次。
   默认一壳一门；壳过大时按 S 条目分里程碑各设门。demo 门验收结论写壳「过程与证据」节
   （带日期戳）。不新设轮次（ADR 0021 轮次上限不变）。
3. **范围锁死**：实现不得超出 `docs/design/` 文档与已批计划壳的范围；发现缺失功能 → 先回
   文档面补设计 → 用户裁决 → 再实现。「文档未提及的功能不加」由惯例升格为
   [code-standards.md](../standards/code-standards.md)「允许与禁止清单」的禁止项。

考虑过的替代方案与排除原因：

- ① **按版本号一刀切豁免（用户原案）**——排除：版本号与数据可再生性无关，会让「备份确认档」
  数据在 1.0 前裸奔；改判后用户确认。
- ② **自由重建档也保留一条 mysqldump 后路（agent 原案）**——排除：用户裁决测试库与 LLM
  调用账免备份；备份临时制 + 验收即清已覆盖真正需要回滚的场景，低价值数据留 dump 只会
  制造 ADR 0019 背景节所述「能否回滚」误判与残留。
- ③ **第一性原理独立成标准条款**——排除：不可守护、与既有「一句话成功标准」重复；熔进
  demo 门条文 + AGENTS.md 决策机制行半句（「方向取舍以核心价值为准绳（第一性原理，
  非强制）」）。

## 后果

- **正面**：1.0 前 schema 迭代不再被四步仪式拖慢；数据保护判据从「版本」换成「再生成本」，
  与真实风险对齐；大任务的人类验收点从「全做完」前移到「核心可跑」，返工半径缩小；范围
  锁死堵住功能蔓延，文档先行链路（裁决先落笔 → 开始执行 → 实现）闭合。
- **负面/代价**：自由重建档免备份意味着误判档位即丢数据（缓解：档位归属以 database-design.md
  明文清单为准，判不清先按备份确认档走，降档须用户裁决）；demo 门增加一次人工验收等待
  （缓解：一壳一门为默认，不逐里程碑强制）。
- **中性**：生产库红线、四步窗口在备份确认档与生产场景的适用性不变；
  `qed-db-alter-redline-window` 技能不废除，适用面收窄为「备份确认档 + 生产窗口」。
