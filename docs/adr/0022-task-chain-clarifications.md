# ADR 0022：任务治理链路口径澄清（缺陷登记·关闭结果·成功标准冻结·归并裁决）

状态：Accepted
日期：2026-09-30
领域：工程治理
决策阶段：v0.1
取代：—
被取代：—

## 背景

2026-09-30 对任务治理链路做一次全链条梳理（`standards/task-lifecycle.md` + `adr-governance.md` +
ADR 0016/0020/0021 + 六枚契约守护 + `qed-*` 技能 + `guides/development.md` + `AGENTS.md` 分级表），
发现规则本身没有互相打脸的地方说不清、同形任务给出不同结论：

- **两条相反要求**：[ADR 治理](../standards/adr-governance.md)与[任务生命周期](../standards/task-lifecycle.md)
  「计划准入」写「B、C 类**必须**建立独立计划」，而「缺陷处理」写「缺陷修复**不**单独建立计划」——
  缺陷修复多数是代码改动（B 类），两条对同一工作给出相反结论，实际执行一直按后者走却无前者的字面约束。
- **同形不同值**：残余移交型关闭的关闭结果没有口径。REQ-098（W5 移交 ARCH-025 线 1）记 `Achieved`，
  REQ-006（学习界面移交 ARCH-027-M1）记 `Partial`——同样的「有达成项 + 有移交残余」得到两个取值，
  后续接手者无法预判，completed.md 的枚举失去可比性。
- **任务越滚越大**：滚动轮次与长期壳的「目标与成功标准」在实施中被追加，一个任务行随时间承载越来越多
  不相干的工作（判例：稳定性轮从仪表盘状况卡扩到批次水位、存储轮从目录约定扩到元数据岛禁令）。
  扩载使「关闭条件」失去可判定性，也是「只建不收」的另一半成因。
- **改判他轮无准入**：把别的轮次的行改 `类别`、挪归属节（ADR 0021「归并不删壳」）在任何准入表里都没写
  需要用户裁决，本次靠会话裁决补齐，规则缺位。
- **技能副本无正本**：`AGENTS.md` 同时声明全局 `~/.config/opencode/skills/` 与项目 `.qoder/skills/`
  两套同源技能，本仓库 agent 只能读后者；口径更新（ADR 0020/0021）实际只落到 `.qoder` 侧。
  （修订：2026-10-20 用户授权取消 opencode 工具层、单端只服务 Qoder，本条背景所述的双套同源状态已不存在；
  判据不变，现行落点见决定 6 的修订注记与根 `AGENTS.md`「协作流程」。取消不另立 ADR。）
- **证据要求与现实脱节**：「Achieved 须提交 hash」是标准口径，但项目常在未提交态收口（用户逐次批准提交），
  按字面执行等于每轮收口都在违规。

## 决定

1. **缺陷登记是 B 类计划准入的已裁决例外**：可复现缺陷以**承载轮壳登记表条目 + 回归测试**替代独立计划，
   不为其单建 `plans/` 壳；「B、C 类必须建独立计划」不适用于缺陷类工作。关闭条件仍是回归测试通过。
2. **缺陷与设计小修两通道的判据**：改动落在**代码行为**（含端点、状态机、UI 逻辑）→ 登记 `DEFECT-NNN`
   入 todo；改动只落在**文档正文**（设计描述错漏、措辞、契约文字）→ 登记
   [设计类小修与 bug 修复台账](../plans/design-bugfix-log.md)，不入 todo。同一现象两边都有记录时，
   todo 行为事实源、台账条目为文档侧留痕（判例：DEFECT-006 与 BUGFIX-023）。
3. **关闭结果按「本任务成功标准是否全部达成」取值**：
   - 成功标准全达成，残余只是后续观察窗、他人排期或承接方的在途工作 → `Achieved`（判例：REQ-098）；
   - 成功标准中存在**未做的核心项**，无论其去向（移交、后置、放弃）→ `Partial`（判例：REQ-006）；
   - 判定依据是壳「目标与成功标准」列出的条目本身，不看工作量大小，也不看移交文字写得多完整。
4. **成功标准冻结与不扩载**：计划壳的「目标与成功标准」经用户评审确认后即为该任务的**范围上限**。
   后续新工作只能二选一——① 在同一目标下往壳的「工作项」表加**条目**；② 另登 todo 行或另建壳（按
   ADR 0021 第 1 条先找承载）。**不得**通过追加、改写「目标与成功标准」把新工作并入既有任务，也不得
   把既有壳改判扩范围；确需改动该节必须经用户确认，并在壳内留下一行裁决记录（日期 + 改动理由）。
   长期滚动壳同样受约束：其「无终态」豁免只免除收口节拍，不免除范围冻结。
   （勘误：2026-10-01 按 [ADR 0023](0023-todo-row-carries-scope-and-criteria.md) 决定 2，本条冻结
   对象由壳「目标与成功标准」节移至台账行的「成功标准」列，壳只留目标陈述与指针；
   冻结判据不变。）
5. **归并、降级与改判他轮归属须用户裁决**：任何改动他轮/他行的 `类别`、归属节或承载关系的整理动作
   （含 ADR 0021 第 5 条「归并不删壳」、G6 触发的残留支线并节）必须由用户发令；agent 不得自行降级、
   挪节或改归属。裁决须在承载壳或对应 ADR 留一行记录。
6. **技能正本为项目 `.qoder/skills/`**：本仓库治理技能（`qed-intake` / `qed-plan` / `qed-implement` /
   `qed-closeout` / `qed-frontend-check`）以 `.qoder/skills/` 为唯一正本，随 ADR 同批更新；其他 agent
   侧的副本（如 `~/.config/opencode/skills/`）不由本仓库 agent 维护或校验，`AGENTS.md` 按此声明。
   （修订：2026-10-20 用户授权取消 opencode 工具层、不另立 ADR——三仓 `.opencode/skills` 联接与根
   `opencode.json` 已删除，机器级配置目录改名停用为 `~/.config/opencode.disabled-2026-10-20`（可逆备份）。
   本条**判据不变**（L2/L3 正本是各仓库 `.qoder/skills/`，agent 端直读正本、不持有副本，副本差异不计为缺陷），
   变的是事实层：已无「其他 agent 侧副本」需要声明，故三分句自本日起只作历史口径；三层模型与端无关防线
   正文见根 `AGENTS.md`「协作流程」，本 ADR 状态与其余六条决定均不变。）
7. **关闭证据允许「待提交」占位**：收口时改动尚未提交，可写 `待提交（用户发令提交后由收尾会话补登 hash）`
   并在 completed.md 留同一注记；**无 hash 不构成拒绝关闭的理由**。用户发令提交后，收尾会话在下一次
   触达该台账时补登提交 hash。
   （勘误：2026-10-01 按 [ADR 0023](0023-todo-row-carries-scope-and-criteria.md) 决定 5，本条占位
   落点移至计划壳「## 过程与证据」节与 completed.md，不再写 todo 行；口径不变。）

## 后果

- 「缺陷要不要建计划」「移交算 Achieved 还是 Partial」两类反复发生的判断有了单点答案，不再靠读者自行
  调和两条相反规则；标准文本相应以判据句承载，不再靠上下文推断。
- 成功标准冻结补上了 ADR 0020/0021 未覆盖的第三条成因：0020 管「该收不收」、0021 管「该挂哪儿」，
  本决定管「一个任务能长多大」。代价是滚动轮次的目标表述必须在立项时写准，扩范围要走确认 + 留痕。
- 决定 4 与决定 5 暂无契约守护（守护增量属另批裁决，本 ADR 不夹带实现）；执行面由 `qed-plan` /
  `qed-closeout` 的自查步骤承接，收口时按「壳的目标节是否被改过」「他轮行归属是否被挪过」两处对照。
- 技能口径不再假设双侧同步：以 `.qoder/skills/` 为准，其他副本的差异不作为本仓库缺陷计数。
  （2026-10-20 起该副本层已随 opencode 工具层取消而不复存在；本条后果继续有效，用于兜住任何未来出现的
  端侧副本——正本定义仍是单点，副本差异不计缺陷。）
- 证据占位让「台账收口」与「git 提交」解耦，符合本项目提交逐次人工批准的权限现实；副作用是 completed.md
  可能短时期存在「待提交」行，由后续收尾会话补登收敛。
- 不取代任何现行 ADR：本决定是对 [ADR 0016](0016-todo-registration-one-task-one-plan.md)（登记形态）、
  [ADR 0020](0020-task-closure-cadence-and-thin-registration.md)（关闭节拍与证据）与
  [ADR 0021](0021-round-proliferation-cap-and-per-row-doc-anchor.md)（承载归属）的**口径澄清与补充**，
  三者状态与决定内容均不变，属 [ADR 治理](../standards/adr-governance.md) 意义上的正文关联。
