## 1. 定位与两部分分工

前端只有两大部分，**分工明确、互不越界**：

| 部分 | 面向 | 职责 | 铁律 |
| --- | --- | --- | --- |
| **学习中心** | 学习者 | 展示**已成品**、协助学习：知识探索、课程学习、课后练习 | **零过程性内容**——下载、解析、分析等生产过程不得出现在此；只告诉/展示「怎么学」，不涉及「怎么开发/怎么加工」 |
| **后台管理** | 管理者（专业用户） | 管理**全过程链路**：文档下载 → 解析 → 文档分析处理 → 问题定位（系统） | **不辅助学习**——过程性、专业性为主，保证链路可管、可查、可定位；产出交学习中心消费 |

**分界原则**：后台管理把原始文档加工成「可学习的成品」（确认的知识点、编排好的课本学习链路、
关联好的课后习题及讲解）；学习中心只消费这些成品。两侧之间是**生产者 / 消费者**关系，
学习者永远看不到生产过程，管理者不需要被「引导学习」。

## 2. 视觉总则（正本）

（2026-10-15 自 [frontend-architecture.md](../../architecture/frontend-architecture.md)「主题与视觉规范」节迁入，本文自此为视觉规范唯一正本；架构文改指针。）

- **主色调**：蓝 / 白 / 黑。主色 AntD 蓝色系（如 `#1677ff` 系）；背景白色 / 浅灰蓝；正文默认黑字。辅以浅蓝渐变卡面。**简洁风格**——留白充分、装饰克制、信息密度以「一眼看清」为准。**色值以 `web-ui/src/theme.ts` 为唯一正本，本文只定方向、不列精确令牌表。**
- **文字对比度门禁**：无论何时何地，字体与背景保持大区分——正文深色底不配深字、浅底不配浅字；状态色文字必配同色系浅底。
- **缩放自适应**：整体布局随浏览器大小自适应（Grid / Flex + AntD 响应式栅格 + 断点），不依赖固定像素布局。
- **一致性**：全部界面共用 `web-ui/src/theme.ts` token 与通用组件（状态点、卡片、筛选器、空态 / 离线态），筛选 / 卡片 / 状态点风格统一；新增界面 / 组件不得绕过 theme token 自定配色。
- **跨面页头动作组（四面同位同顺序）**：首页／知识探索／课程学习（书架＋工作台）／课后练习四面的导航右上角＝**使用手册／刷新／返回**，返回固定**末位**、回根页面 `#/`，同款蓝底白字；「刷新」＝只重取本面数据，不触发任何生产动作。面内自有出口（如工作台课程名右侧「返回书架」）属面内规格，由各面详设定，本文不复制。
- **对齐与形态常量化**：列表／目录行的左缘由组件内**具名常量或常量函数**单源给出，同档各行左缘必须相等，不写散落的 `marginLeft`；antd v5 `Button` 的内容容器是 `display:inline-flex; justify-content:center`，**单写 `textAlign:'left'` 对 flex 主轴无效**（左缘随文本长度漂移），对齐一律显式给 `justify-content` 并在用例里断言它。版式／形态类改动的验收口径＝按 [`qed-frontend-check`](../../../.qoder/skills/qed-frontend-check/SKILL.md) 做 `innerWidth` 三档实测并记录文本左缘读数。
- **暗色承载例外（一处）**：**页面本体**＝星图页 `#/knowledge` 用**页面局部** `ConfigProvider` 暗色承载星空背景，不动全局 token、不影响后台管理浅色。例外只此一处，再扩面须重新裁决。
- **使用手册弹窗承载（2026-10-16 用户改判，撤销同日 REQ-117 C12 的「深蓝底白字」）**＝**蓝框白底深字**：面板底与正文同为浅色，**文字一律落在白底上**，深蓝只作**外框与标题/强调**（框 `2px solid #0b2472`，节标题与入口名同色，次级字 `#4a5a78`，链接与箭头 `#1677ff`，入口卡＝白底＋蓝细边＋悬停浅蓝底）；浅底必配深字，禁在同弹窗内混用深底浅字。星图页内的手册弹窗同样走此浅色承载，不随页面本体转暗。**手册形态**：每册恒为功能概览→使用说明→状态与限制三节，**总册的三条入口卡排在「使用说明」之后**（先读完怎么用，再挑要进哪一面），入口卡内文字用两列栅格（箭头列定宽＋文本列），名称行与说明行左缘同列、行高一致，三卡宽度与文字起点齐平。

## 3. 文案与语言风格

- **语言**：界面语言中文；标识符 / API 字段保持英文（全仓一致）。
- **术语一致**：领域 / 课程 / 教程 / 书目 / 知识点 / 章节单元 等核心名词全前端统一，不在不同界面换词。
- **状态徽章词本身承载口径**：徽章文案必须自解释（如 `draft`＝「待建链路」/「草稿」、`learning`＝「在学 N%」、`completed`＝「已结课」），不依赖小字脚注或悬停才说清；多口径各给一个徽章文案，避免误读。
- **两侧语气分离**：
  - 学习中心＝**引导性、面向学习者**，不出现技术 / 生产过程术语（「解析」「下载」「OCR」「bbox」「链路」「编译」等不入学习面文案，课程学习面口径见 REQ-117 裁决 C3）。
  - 后台管理＝**专业、精确**，可直接使用技术术语与状态机口径，服务管理者定位问题。
- **过程性内容隔离**：下载 / 解析 / 分析等过程状态只在后台管理呈现；学习中心只呈现成品结果（知识点、链路、习题）。

## 4. 前端视角全流程

从前端看，一份原始文档到学习者可学，经过如下链路（**前三段属后台管理，末段属学习中心**）：

```
① 文档下载            ② 文档解析            ③ 文档分析处理           ④ 学习中心消费
（QED-Tracker         （Axiom-Flow          （后台管理·新模块         （学习中心）
 发现/下载/校验/登记）    OCR/公式/图表还原）     分析产物→目录生成修正    知识探索 / 课程学习 /
                                              +登记确认知识点           课后练习
                                              +编排课本学习链路
                                              +关联课后习题及讲解）
   后台管理 ─────────────────────────────────────────────┘         └── 只消费成品
```

- **①→②→③ 是过程链路**，全在后台管理侧，管理者可管、可查、可定位问题。
- **③ 文档分析处理是「过程 → 成品」的最后一道加工**：解析产出的是版面 / 块级内容，分析处理把它提炼为**语义成品**——① 生成并人工修正课本目录；② 登记并确认知识点（确认／驳回的唯一写面）；③ 展示 / 编排合适的课本学习链路；④ 关联对应课后习题及其讲解。分析驱动＝**LLM 自动分析 + 人工确认**；后续具体细节（分析算法、后端端点、习题讲解来源）由 **Axiom-Flow 负责**，根侧设计稿见 [REQ-116 文档分析处理设计稿](../../plans/2026-10-15-doc-analysis-processing.md)。
- **④ 学习中心只消费 ③ 的产出**：知识探索浏览已确认知识点、课程学习按**已确认知识点**逐条推进、课后练习用已关联习题作答。学习中心不触发、不展示 ①②③ 的任何过程。

## 6. 边界铁律

- **唯一入口**：浏览器只连 8900（ADR 0007），不直连 8901 / 8902；前端自身不提供 API。
- **学习中心零过程性**：下载 / 解析 / 分析的状态、进度、技术术语一律不入学习面。
- **后台管理零学习辅助**：管理面不承载「引导学习」的交互与文案，只做生产与管理。
- **独立性降级**：8901 / 8902 离线时各视图显示离线提示 / 降级，不白屏不报错；8900 离线时页面本地判定兜底 + 错误横幅（铁律见 [frontend-architecture.md](../../architecture/frontend-architecture.md)）。
- **范围锁死（ADR 0024）**：本文与各模块详设未提及的功能不加；缺失功能先回文档面补设计再裁决。
