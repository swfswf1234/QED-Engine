## 1. 定位与目标

本文档是文档下载管理页（`#/admin/downloads`）的 **UI 设计事实源**：左树结构、右侧
四层展示、筛选与排序规则、弹窗（含论文探索弹窗与领域论文栏）、三层状态口径声明，以及
异常与降级的**用户可见表现**。它回答的是「用户在下载管理页看到什么层级、能做什么操作、
依赖离线时页面怎样表现」，以及「系统按什么口径找论文、用户如何逐条决定收进书库」。

- **目标**：领域→课程→教程→书目四层内容一屏可导航可维护，状态口径与后端状态机严格
  对齐、互不混用；
- **成功标准**：本页全部前端展示行为（含右键菜单门禁、筛选档、弹窗操作区、降级横幅）
  均有唯一口径可查；任何 UI 改动不混用 §5 三个状态体系的字段来源。

## 2. 范围与非目标

**范围内**：本页全部前端展示层（树/卡片/弹窗/筛选/排序/样式/异常降级表现）。
**非目标**：不涉及后端 8900/8901 改动；不请求 QED-Tracker 接口变更（教程命名由其数据侧
执行，前端 name 空值兜底见 §7）；不拆分 en 套为独立教程行（排序规则已置组尾）。

本档**不**维护以下内容，逐条给出唯一事实源指针（[ADR 0017](../../adr/0017-design-doc-structure-contract.md) 事实源唯一铁律）：

## 3. 左树结构（领域 → 课程 → 教程 → 论文）

```
▸ <领域>（共享表领域清单，多领域；DomainCard 恒显不受筛选影响）
  ├─ <课程>（可折叠；点击 = 选中 + 联动筛选）
  │   ├─ 教程1：<书名>（<作者>）      [3/4 已验收]
  │   └─ 教程2：…                    [5/5 已验收]
  ├─ 论文（k）（派生视图叶子节点；点击 = 该领域论文全量栏）
  └─ …
```

- **领域**：来自 `GET /courses` 领域清单；名称/描述/阶段徽标/explore_pending 提示条由
  DomainCard 呈现（右侧恒显，见 §4.1）；左树支持右键维护（编辑/删除/探索领域知识/
  导入领域知识/添加课程/**论文探索**）。右键菜单门禁：探索在 `未开始/已生成/待确认/失败`
  可用（`探索中` 除删除外全部禁用）；**添加课程在 `未开始`/`已生成` 禁用**，`待确认/已完成/失败` 可用；
  **论文探索不受 exploration_stage 门禁约束**，仅在该领域有在跑论文任务时禁用（§4.4）。
- **课程**：点击选中 + 联立筛选；右键菜单（编辑/删除/课程探索/导入教程，按探索状态禁用，
  见 [downloads-flow.md](../downloads-flow.md) §3.3 操作表）。
- **教程**：叶子节点，只展示 名称 + 验收进度数字（`verified 数/总数`），不可点击展开；
  书籍明细只在右侧栏/弹窗查看。
- **论文**：每个领域节点下、课程之后固定追加的**派生视图叶子节点**（不是课程，不落任何
  课程记录），右侧计数＝该领域 `kind=paper` 书行数（含落位到该领域课程的论文）；选中后
  右栏进入该领域论文全量栏。节点语义与铁律见 §4.4.6，不读也不写 `exploration_stage`。
- 树宽拖拽（280–640px、localStorage）与默认展开/折叠状态保留。

### 3.1 领域维护表单（字段口径与默认值）

三处入口（左树底「添加领域」、右键「编辑领域知识」、领域确认弹窗）字段集合与顺序统一：

| 顺序 | 字段 | UI 标签 | 添加时默认值 | 口径 |
| --- | --- | --- | --- | --- |
| 1 | `name` | 领域名（必填；创建后不可改） | 空 | 领域探索的强输入 |
| 2 | `description` | 领域描述 | 默认句（随领域名插值，见下） | 用户对该领域的既有定位说明；**用户写过的描述是权威内容，领域探索结果不得覆盖** |
| 3 | `scope` | 学科知识 | 默认句（见下） | 探索的范围边界；用户填写值优先于内置默认边界 |
| 4 | `level` | 探索范围 | `本科-硕士` | 默认学习层级与范围，兼作课程体系梳理的范围提示 |
| 5 | `stages` | 学习阶段 | `基础,主干,分支,前沿` | 阶段序列，与 QED-Tracker 侧四档阶段常量同值域 |

默认句正文（前端预填与此处一致，不在代码侧另写措辞）：

- `description`：`{领域名}：本次新增的待探索领域。用户对该领域的既有认识见「学科知识」，
  层级与阶段见下方参数；请据此梳理学科定位、研究对象与主干课程方向。`
- `scope`：`学科知识以中文记录与表述；知识体系、课程划分与前沿参照美国主流高校（本科至硕士）
  的通行方案，教材与文献可保留英文原版，专业术语给出中英对照。默认覆盖本科—硕士阶段，
  超出该范围的内容不进入本次梳理。`

- **五字段一律是领域探索的输入**；标签里的「可选」只表示留空由默认值承担，不表示可忽略。
- **标签唯一口径**：「探索范围」只用于 `level`，`scope` 一律称「学科知识」，两处不得互换；
  领域确认弹窗与两个维护表单使用同一组标签。`name` 行的差异只有后缀提示：添加表单为
  「领域名（必填；创建后不可改）」，两个维护/确认表单为只读的「领域名」（领域已建，改名不在此处发生）。
- **描述可空**：三处表单的 `description` 均为非必填（空值由探索生成或保留默认句），
  领域卡对空描述显示「（暂无描述，可点『探索领域知识』生成）」。

**消费现状（未接通面）**：8901 领域探索后台任务当前只把领域名送入 domain 提示词，
`description/scope/level/stages` 既不进入提示词，库中值还被探索结果就地覆盖（`description`、
`stages` 恒被输出替换，`level` 仅输出缺失时回退）；`scope` 全程无人消费。四字段的真读取与
「用户写过的描述不被覆盖」已按跨项目请求登记（见 [todo.md](../../trackers/todo.md) 请求行与
QED-Tracker 滚动缺陷台账）。接通前，本表单默认值只决定入库初值与领域卡展示，不影响探索输出；
设计正文描述的是目标态契约。

## 4. 右侧栏

### 4.1 展示层级规范（领域/课程/教程/书目四层）

| 层 | 展示 | 承载 | 可用操作 |
| --- | --- | --- | --- |
| 领域 | 名称、描述、阶段徽标、explore_pending 提示条 | `DomainCard`（**无论筛选如何恒显**） | 探索/确认领域/确认课程（按 [downloads-flow.md](../downloads-flow.md) §3 状态机）；失败态 danger 重试 |
| 课程 | 名称、描述 + **操作条：课程探索、导入教程** | 课程头（`dl-course-head`） | 编辑/删除（左树右键）；课程探索在 探索中/已完成 禁用 |
| 教程 | 名称（`.dl-knowledge-name`）、状态、**进度（下载 x/y 本）**、详情 | 教程行 | 详情（弹窗）、自动下载（candidate/decided/failed 可用）、删除（`DELETE /knowledge/{id}`） |
| 书目 | 书名、作者、语言、**版本标签**（中译本/英文版/苏版/其他，由 language 与书名/作者推导） | 书目卡（纯展示，无操作按钮） | 详情（弹窗：信息 + 下载信息 + 上传/验证/自动下载）；新增书目在**教程详情弹窗**内 |

四层之外另有第五个展示组——**领域论文栏**（左树「论文」节点选中后的横向卡片列，见 §4.4.6）。
领域与课程行内**不再有论文展示行**：发现论文只有这一处全量视图，教程行内的书目卡 kind
标签与排序规则不受其影响。

**教程详情弹窗**（`TutorialDetailModal`）：教程信息（修改入口经 `PATCH /knowledge/{id}`）、
书目列表（书名/作者/语言/状态/操作）、**新增书目**（`POST /books` 书库化创建：`book_id`
格式 `{abbr}-b{NN}` + 书名必填，归属由教程 refs 承载）、书行**上传**
（浏览器文件选择器 → `POST /books/{id}/import` multipart，**不写路径**）。

**书目详情弹窗**（`BookDetailModal`）：

- 尺寸：宽 `760px`，内容区 `max-height:68vh` 滚动，窄屏 `max-width:94vw`。
- 标题：`书目详情 · {书名（含卷册）}` + 状态 Tag。
- 区块一「书目信息」：两列网格——书名 / 原版书名 / 卷册 / 版本 / 作者 / 出版社 / 出版年 /
  语言 / 角色 / 页数。
- 区块二「下载信息」（**只两行**）：下载状态（成功 = `holding=owned` 且 `status ∈
  {downloaded, verified}` ｜ 失败 = `status=failed` ｜ 未下载）+ 文件地址（`file_path`，
  无则 `absolute_path`，均无「—」）。
- 渠道尝试折叠块「查看渠道尝试（N）」，默认收起（排障用）。
- 操作区（footer）：`上传书籍`（文件选择器，任意状态）｜ `自动下载`
  （candidate/decided/failed）｜ `验证通过`（downloaded）｜ `关闭`。
- 行为：操作后以服务端返回为准（禁乐观更新）；上传成功就地更新为 `downloaded`。

**统一上传原则**：领域 JSON / 课程 JSON / 书籍 PDF 三类入口一律用
浏览器文件选择器，界面不出现文件路径输入框。书目卡**不显示 kind 标签**（与 roles 语义重复）。

### 4.2 筛选规则

| 筛选项 | 规则 |
| --- | --- |
| 领域筛选 | 树聚焦该领域；领域信息卡仍恒显 |
| 课程筛选 | 只显示匹配课程的下游内容 |
| 状态筛选（书籍阶段） | 无匹配书籍的教程整行隐藏；无匹配教程的课程整组隐藏 |
| 汇总行 | 「当前选择：领域/课程 ×」「筛选结果 N 条教程」两行文字左靠，右端同一排挂**该领域论文活动态徽标 + [论文探索] 按钮**（§4.4.1；rejected/superseded 由数据层隐藏） |

**流程筛选 → 书籍状态映射**（**5 档**；与代码
`stores/downloads.ts` `bookInStage` 一致）：

| 筛选档 | 书籍状态 |
| --- | --- |
| 待下载 | candidate / decided |
| 下载中 | downloading |
| 待验证 | downloaded |
| 已完成 | verified |
| 失败 | failed |

`parallel`（平行读物）不计入筛选，`retired`（退役）留痕隐藏。

### 4.3 书籍排序（`sortBooks`，每教程行内）

1. 组序：① 中文教材（language=zh 且 kind=textbook）→ ② 中文习题集（language=zh 且
   kind=exercise）→ ③ 其余（英文教材、配套资料、论文等）。
2. 组内按册数递增：`part` 解析——第一册=1…第五册=5；上/中/下册=1/2/3；单册（part 空）=0
   排组首；答案册=99 排组尾。
3. 同册数按 title 稳定序。

### 4.4 论文探索弹窗与领域论文栏

**语义切分**：本节承载**发现论文**——领域级探索、逐条落位的 `qt_books` kind=paper 行且
**refs=domain_id/course_id**；教程挂靠的论文（refs=knowledge_id）属教程附属资料，仍按 §4.1
口径显示在教程行内。两类以 refs 区分，互不混列。链路、状态派生与写点口径的唯一事实源是
[downloads-flow.md](../downloads-flow.md) §7，本节只规定展示形态。

**数据源**：发现论文书行经 `GET /api/v1/papers/books` 枚举（8900 透传面，登记于
[api-contracts.md](../../architecture/api-contracts.md) §③；8900 `GET /books` 是 Axiom af_books
代理，不可复用）。端点未实装或拉取失败（含 404）时**静默按空集处理**，论文栏显示空态，
不进错误横幅、不打扰用户。检索与评分实现（计划生成、arXiv 检索、三维打分、加权合成）在
8901/8900 侧，界面**只读服务端结论字段**，不复制权重、推荐线与候选上限为前端判断常量。

#### 4.4.1 入口（三处同弹窗，首屏恒为段①）

| 入口 | 位置 | 禁用条件 |
| --- | --- | --- |
| 领域右键「论文探索」 | 左树领域节点右键菜单（§3） | 该领域有在跑论文任务；**不受 exploration_stage 门禁约束** |
| 汇总行「论文探索」按钮 | §4.2 汇总行右端 | 未选择领域/课程时置灰；课程选中取其所属领域，所属领域不存在则置灰 |
| 论文栏空态「发起论文探索」 | §4.4.6 | 无 |

三处一律打开同一弹窗，首屏都是段①探索设置（该领域已有论文与否都能进）。课程语境不设独立
探索入口。弹窗标题带语境：`论文探索 · {领域名}`，从课程语境进入为
`论文探索 · {领域名}（{课程名}）`（实际探索仍按所属领域发起）。

**按钮与活动态徽标的位置**：汇总行容器为 `display:flex; align-items:flex-start`，左文字块
（「当前选择…」与「筛选结果…」两行）占 `flex:1`，按钮 `margin-left:auto` 贴右缘、与第一行
「当前选择：…」**同一排**，不下沉到两行文字之下。该领域论文活动态徽标（探索中／待评审／失败，
派生条件见 [downloads-flow.md](../downloads-flow.md) §7.2）渲染在按钮**左侧**；`已沉淀`／`隐藏`
两态不显示徽标。**领域/课程行内不再有论文展示行**——发现论文只在 §4.4.6 的领域栏出现。

#### 4.4.2 弹窗五段

| 段 | 名称 | 内容 | 出口 |
| --- | --- | --- | --- |
| ① | 探索设置 | 检索方向（四值单选，§4.4.3）→ 领域描述（只读 `domain.description`，括注「本次探索目标缺省取此」）→ 探索目标（可选文本）→ arXiv 分类（可选，留空＝按领域关键词映射）→ 一行口径说明 → 历史探索清单按钮（§4.4.5） | `发起探索` |
| ② | 探索进行中 | 每 5s 轮询任务与报告态；文案按 `task.message` 区分计划生成／检索中／评分中 | 成功自动进③；失败给原因 + 改参数出口 |
| ③ | 检索口径 | 顶部 `模型计划`／`兜底计划` 徽标（兜底用警示色）；逐条计划表（序号｜关键词｜分类｜生成理由｜抓取 fetched｜保留 kept）；档案摘要行（goals／topics／年窗／allowed_categories）；一行汇总 `排除已在库 N 篇 ｜ 去重后候选 M 篇`；`search_failures` 非空时逐条列 | `进入候选评审`（唯一前进路径）／`收起` |
| ④ | 候选评审与采纳 | 头部计数行（§4.4.4）；只列待选区间条目，行内可就地展开详情（§4.4.7）；逐条落位选择（本领域／该领域下任一课程）；`采纳所选（不自动下载）` | 提交后进⑤ |
| ⑤ | 采纳回执 | 逐条 `book_id` 与「已入库／重复」结果；一行提示已采纳论文去左栏**论文**节点查看 | 关闭弹窗，论文栏卡片就地刷新 |

- 段①不出现「推荐上限」一类调配面（一次探索恒 5 篇，§4.4.3）。
- 界面不出现「权威」字样；候选第三段说明一律称**评审小结**（现链路没有生成式「总结」字段）。
- 弹窗状态挂在 store，关闭不丢。
- `no_candidates` 与 `no_recommendations` 在段③给区分文案（前者＝检索没取回候选，
  后者＝有候选但没一条达到服务端推荐线），各给回段①的调参出口。

**口径透明纪律**：段①发起前的参数摘要行与段③都要显示**实际下发**的目标串与年窗，不得只在
后台改；`plan_source` 必须可见，兜底属降级，界面须警示并列出 `search_failures`。具体检索关键词
只能任务成功后展示——检索计划由模型在任务内生成，发起前只能说明口径（年窗／抓取量／分类来源／
目标），不能预告关键词。

#### 4.4.3 检索方向 → 请求参数映射

「检索方向」是界面概念；落到请求体＝(`recipe`, `years_limit`, `limit`, `goal` 追加语) 四元组，
`top` 恒 5。`recipe` 值域在服务端封闭（`frontier`／`core`），深度／匹配**别名复用**配方 +
参数覆盖，不新增 recipe 值。

| 方向 | recipe | years_limit | limit | goal 追加语 | 语义 |
| --- | --- | --- | --- | --- | --- |
| 前沿 | `frontier` | 缺省（3） | 缺省（15） | 无 | 近年新鲜度优先 |
| 核心 | `core` | 缺省（不限年） | 缺省（20） | 无 | 不限年、少而稳 |
| 深度 | `core` | `0`（显式＝不限年） | `25` | 「侧重证明细节、方法论与理论深度」 | 年窗最宽、每组抓取量拉满 |
| 匹配 | `frontier` | `10`（放宽年窗） | `20` | 无——但**探索目标必填** | 与本次目标契合优先 |

- 匹配方向在探索目标为空时于段①内联提示并**禁用发起**（不改服务端；服务端允许 `goal` 空）。
- 达线数上限即 5；放宽容量的出口是**换检索方向**（深度／匹配放宽年窗与抓取量），不是调 `top`。
- 服务端边界（`limit` 1–25、`years_limit ≥ 0` 且 0＝不限年、`top` 1–20）只作取值依据说明，
  根侧不复制为前端校验常量；越界由服务端返 422，按现通路显示原因。
- 映射的执行正本＝纯函数 `web-ui/src/paperDirections.ts`；本表是其唯一设计事实源。

#### 4.4.4 待选区间（段④列表判据）

**待选区间＝同时满足四条**：

| 判据 | 字段条件 | 承载 |
| --- | --- | --- |
| 高相关度 | `assessment.goal_fit ≥ 4` | 三维中唯一表达「与本次探索目标契合」的量表（0–5） |
| 总分抬高 | `score ≥ 80` | 界面层额外门槛，与服务端推荐线并存、不互相覆盖 |
| 服务端推荐 | `recommended === true` | 只读服务端结论布尔；界面不重算权重 |
| 未在库 | 不命中「已入库 ∪ 已采纳」arXiv 标识集合 | 达线但已在库／已采纳者移出待选，计入剔除数 |

- 剔除集合的前后端分工：服务端只剔**已取到文件**的论文（报告 `excluded_existing`）；
  **已采纳但尚未取书**的论文由前端按本地 `kind==='paper'` 书行的**标题归一匹配**剔除
  （书行不携带 arXiv 字段，逐本回源违背 §4.4.7 按需纪律）；两者取并集、不重复计。
  故「下次探索剔除已选择的部分」＝后端剔已入库 + 前端剔已采纳，两条都在段④头部说明。
- 头部一行：`候选 N 篇 ｜ 待选区间 M 篇（未达线 X 篇）｜ 已剔除 J 篇（已采纳／已在库）`。
- 待选条目**默认全选可改**；未达线与已剔除条目折叠在「查看未入选」区，**只读不可勾选**
  （门槛不可绕过），每条注明唯一归因（按序取第一个不满足项）：`相关度 x＜4` → `总分 y＜80`
  → `超出本次推荐上限` → `已采纳／已在库`。
- 达线数为 0 是**预期结果不是故障**（门槛按使用者口径刻意收紧）。空态区分两种：「本次没有达到
  待选门槛的论文」与「本领域达线的论文都已采纳或已在库，换个检索方向再探索」，各给回段①出口。
- 判据的执行正本＝纯函数 `web-ui/src/paperShortlist.ts`；本节是设计事实源。

#### 4.4.5 历史探索清单

段①只放一个按钮 `历史探索清单（k）`，常驻收起、不内联展开任何报告内容；`k`＝本领域待决定报告份数。

- 来源 `GET /papers/selections?domain_id=<本领域>&limit=10`（8900 现成透传，零新端点）；
  只列本领域、**不按配方过滤**（一个配方承载两个检索方向，过滤会误删）。
- 点按钮才展开清单：只列**待决定**报告（`status ∈ {ranked, no_recommendations}`，已消费与
  无候选的不进清单），按 `created_at` **新的在前**；行文案 `时间 ｜ 方向 ｜ 状态 ｜ 达线 k 篇`
  （方向按 `recipe` 原样词显示，不假造深度／匹配；计数取 `recommendation_count`，
  报告摘要行没有候选总数字段）。
- 点任一行 → 载入该报告并**直达段④候选评审**（继续确认／否定、就地展开摘要与评审小结）；
  段③仍可经评审段头部「查看检索口径」到达。
- `k＝0` 时按钮禁用并显示「本领域没有待决定的探索报告」；清单拉取失败静默，不阻塞发起探索
  （段①主路径是发起，清单是旁路）。

#### 4.4.6 左树「论文」节点与右栏卡片列

- 每个领域节点下、课程之后固定追加一个子节点**「论文」**——**派生视图节点**，不是课程、
  不落任何课程记录；节点右侧计数＝该领域 `kind=paper` 书行数（含落位到课程的论文，一处看全）。
- 选择模型增 `{kind:'papers', id}`；选中后右栏＝领域信息卡 + **论文卡片列**，与教程列同形
  （`.dl-books-row` 横向滚动、卡片同宽）。
- 卡面只读：标题（两行截断）、年、首位作者、五档状态徽标、页数（有则显示）；落位到课程的
  论文带课程归属标签。卡内不放批量操作，操作留在详情弹窗。
- 点卡 → 书目详情弹窗（`BookDetailModal`）+「探索记录」小节（§4.4.7 按需回源）。
- 空态：「该领域还没有已采纳论文」+ `发起论文探索`（直达弹窗段①）。
- **铁律**：该节点不读也不写 `exploration_stage`，不参与课程六/五态机，不新增表与端点；
  徽标一律沿用 [downloads-flow.md](../downloads-flow.md) §7.2 的派生口径（任务态 × 报告态 × 书行五层态）。
- 写后刷新：采纳成功后论文栏计数与卡片就地刷新（复用书行刷新链，不整页 reload）。

#### 4.4.7 论文详情与按需回源

- **探索段内（尚未采纳）**：点条目就地展开详情——标题、`作者 · 年 · arXiv 链接`、**摘要**
  （arXiv 原文摘要，不改写语言）、**评审小结**（`assessment.reason` 正文 + `risks` 逐条）、
  三维分（`goal_fit`／`foundational_value`／`readability`，各 0–5 原样显示，不换算不加权）、
  总分（服务端已算）、是否入选。
- **已入库**：书行本身只有书目字段（标题／作者／年／出版社／五层态／页数／落位）；摘要与评审
  小结**按需回源**——`GET /books/{book_id}/sources` 取 `channel==='arxiv'` 的 `provider_id`
  → 本领域 `GET /papers/selections` → 逐份 `GET /papers/selections/{id}`，在 `candidates` 中按
  arXiv 标识匹配 → 命中即并排显示书目 + 摘要 + 评审小结 + 分数。
  - 纪律：**仅在用户点击时发起**、只扫当前领域、扫描份数上限 20 份、失败静默降级、
    不缓存全量报告、不为凑数据轮询多领域。
  - 未命中（早期采纳、外部登记、报告已清理）显示「该论文没有探索记录」，书目字段照常，
    不编造摘要。
  - `GET /books/{id}/sources` 失败时详情只给书目字段 + 一行「无法取得 arXiv 标识」，不弹错。
- **引用数**（权威度的替代形态）：现链路不携带该字段，界面**只预留位置**——字段不存在时整位
  不显示（**不显示 0**，不造数据）；将来若接入外部数据源，口径为**只展示、不参与任何门槛**。

#### 4.4.8 规则

- 论文书行**参与 §4.2 流程筛选**（本质是书行，五档映射照用）；不参与 §4.3 sortBooks 三组组序，
  栏内按出版年倒序、同年按 arXiv ID 稳定序。
- 「待评审」「失败」徽标可点击直达管理弹窗对应段（幂等重开，不重复发起任务）。
- 采纳**不自动下载**；取书与 `verified` 仍是显式人工动作（[downloads-flow.md](../downloads-flow.md) §7 铁律）。
- 8903 只连 8900（ADR 0007）：计划、候选、详情、回源、书行全部经 8900；密钥与模型渠道信息不进界面。

## 5. 三层状态口径声明

下载管理页涉及三个状态体系，**层级不同、互不冲突**：

| 口径 | 层级 | 值域 | 事实源 |
| --- | --- | --- | --- |
| 探索状态机（六值） | 领域/课程探索流程 | 未开始/已生成/探索中/待确认/已完成/失败 | [downloads-flow.md](../downloads-flow.md) §3 |
| 书籍状态机 | 单本书目选用 + 生命周期 | 选用 `candidate/decided/parallel/retired` + 生命周期 `downloading/downloaded/verified/failed`（UI 5 档见 §4.2） | QED-Tracker `architecture/database-private-tables.md`（QED-050-D/QED-060），8901 透传 |
| 仪表盘统计四态 | 书籍获取进度派生统计 | missing→decided→downloading→owned（holding×status 派生） | [admin-dashboard.md](admin-dashboard.md) |

流程筛选（§4.2）是书籍状态机在 UI 上的**分组视图**；仪表盘四态是 holding×status 的
**统计派生**。任何 UI 改动不得混用三者的字段来源。

**论文线不是第四套口径**：左树「论文」节点、领域论文栏卡片与汇总行徽标都是书籍状态机 +
论文任务/报告态的**派生视图**（派生表唯一事实源 [downloads-flow.md](../downloads-flow.md) §7.2），
徽标只读任务态×报告态×书行态三源，禁读 `exploration_stage`，不新增状态与写点。

## 6. 状态与降级矩阵（异常与降级的用户可见表现）

后端降级规则本身（8900 如何处理）见 [downloads-flow.md](../downloads-flow.md) §5.4；
本节只规定**前端呈现**：

| 场景 | 用户可见行为 |
| --- | --- |
| 8900 不可达 | 页面顶部错误横幅 + 重试 |
| 8901 离线 | 「降级模式」横幅；树/领域维护/导入可用，探索与教程/书目操作禁用 |
| 探索会话失效 | `active_session=false` → 提示「探索会话已失效，请重试」 |
| 管线失败 | `explore_pending.kind='error'` → DomainCard 红色提示条 + 失败原因 + 重试 |
| 刷新页面 | 未终态领域由 5s 轮询直读共享表恢复感知 |
| API 失败 | toast 透出服务端 detail；乐观更新禁用，以服务端返回为准 |
| 8901 离线（论文面） | 领域论文栏照常显示书行清单；[论文探索] 入口与弹窗提交禁用，浏览与回源失败不牵连 |
| `papers/books` 未实装或拉取失败 | 静默按空集处理，论文栏走空态；不进错误横幅 |
| 论文任务失败 | 汇总行徽标「失败」；弹窗失败段显示 error 与改参数出口（不自动重发） |
| `plan_source` 为兜底 | 段③徽标「兜底计划」+ 警示色 + `search_failures` 逐条；降级必须可见，不伪装模型计划 |
| 达线 0 篇（候选非空） | 段④空态给门槛取值，未入选折叠区逐条归因且无勾选框；门槛是判据不是故障 |
| 摘要字段缺失（历史报告） | 详情「摘要」段显示「该记录未携带摘要」，不回退成空壳标题 |
| 按需回源 20 份未命中 | 「该论文没有探索记录」；书目字段照常，不编造、不扩扫领域 |
| 达线数触顶 | 给出「换检索方向」出口（深度／匹配放宽年窗与抓取量），不暴露 `top` 调配 |

`explore_pending.kind` 值域（后端写点契约，事实源见
[downloads-flow.md](../downloads-flow.md) §5.4）：`review_results` / `name_confirmation` / `error`。

## 7. 教程命名规范（跨项目，请求：QED-Tracker）

- 规范：tutorial 教程 `name = 教程{set_no}：{书名}（{作者}）`（书名作者取自教材决定
  引用 `textbook_ref`；en 套为「教程en：…」）；other_material 归类名不加「教程N」前缀。
- 前端兜底：`tutorialLabel` 在 name 为空时显示「教程{set_no}」。
- 后台管理面不出使用手册（2026-10-15 用户裁决：手册只承载学习中心四页）；课程收集五阶段的业务流程事实源仍在 [downloads-flow.md](../downloads-flow.md) §6。

## 8. 已知约束与维护规则

- 状态口径变化（探索状态机、书籍状态机）先改各自事实源文档，本档 §5 声明表与 §4.2
  筛选映射回核即可；端点形状变化归 api-contracts/QED-Tracker 契约，本档不复制。
- 论文线改动触发条件：入口形态、弹窗分段构成、检索方向参数映射、待选区间判据、详情字段
  来源、左树「论文」节点语义变化 → 先改本档 §4.4；纯样式微调随码走。
- 界面不得出现无数据支撑的措辞（「权威」「总结」）；字段缺失一律整位不显示，不显示 0、
  不造数据；补数据须先改本档再改码。
