## 1. 背景与动机

下载管理（`#/admin/downloads`）左树与右侧栏存在以下问题（2026-08-18 用户裁决）：

1. **左树层级与命名不清**：领域用「分析/代数/概率论与数理统计」三个平级领域，用户期望
   领域固定为**高等数学**一个（更清晰），中间按 **分析/代数/概率** 三类对 13 门课程做
   纯展示分组（无意义仅展示，不可点击），教程为叶子节点只做展示与进度展示。
2. **左树交互不符合预期**：领域节点当前常驻展开不可折叠（期望可折叠）；教程节点当前
   可点击选中（期望不可点击，只展示名称 + 验收进度数字）。
3. **右侧筛选栏语义混乱**：当前三个下拉（领域/课程/状态）中领域概念与新结构冲突；
   用户期望新增**按生命周期（四个流程）筛选**：搜索/确认/下载/验收，并保留原三个
   下拉为容错（树点击已负责领域/课程筛选，下拉保留不冲突）。
4. **书行卡标签重复**：书行卡同时显示 kind（教材/习题集）与 roles（教材/习题），
   语义重复——只保留 roles 一次 + 状态（阶段）。
5. **教程命名不规范**：知识行 name 形如「数学分析原理（Rudin） 套1」，期望
   「教程1：数学分析原理（Rudin）」；命名由 **QED-Tracker 数据侧**统一（跨项目任务，
   见 §4）。
6. **书行排序无规则**：每教程行内书行需按 中文教材 → 中文习题集 → 英文教材及其他，
   组内按册数递增。

## 2. 目标态设计

### 2.1 左树「知识梳理」（领域 → 分类 → 课程 → 教程）

```
▸ 高等数学（领域，唯一；可折叠；点击=全量/清课程筛选）
  ├─ 分析（分类头，仅展示，不可点击）
  │  ├─ 数学分析（课程；点击=选中+联动筛选；可折叠）
  │  │   ├─ 教程1：数学分析原理（Rudin）        [3/4 已验收]
  │  │   ├─ 教程2：微积分学教程（菲赫金哥尔茨）  [5/5 已验收]
  │  │   └─ 教程3：数学分析（陈纪修）            [3/3 已验收]
  │  ├─ 点集拓扑（无教程 → 展开显示「暂无教程」）
  │  └─ …
  ├─ 代数（分类头）
  └─ 概率（分类头）
```

- **领域**：固定唯一「高等数学」，可折叠（折叠后隐藏全树）；点击 → 选中 + 清空课程
  筛选（显示全部）。分类（分析/代数/概率/其他兜底）为纯展示分组标题，不可点击。
- **课程**：13 门按分类归属（`DOMAIN_MAP`），点击 → 选中 + 联立筛选（现有 selectNode
  逻辑保留）；可折叠显示教程。
- **教程**：叶子节点，只展示 名称 + 验收进度数字（`verified 数/总数`，如「3/4 已验收」），
  不可点击、不可展开；书行明细只在右侧栏查看。
- 常量调整（`courseMeta.ts`）：`DOMAIN_ORDER` 中「概率论与数理统计」→「概率」；
  新增领域常量 `DOMAIN_NAME = '高等数学'`。学习中心（`stores/knowledge.ts`）用独立
  `KNOWLEDGE_DOMAINS = ['数学']`，**不受影响**。
- 树宽拖拽（280–640px、localStorage）与默认展开/折叠状态保留。

### 2.2 右侧栏

**筛选栏（四个下拉，AND 叠加）：**

| 下拉 | 选项 | 说明 |
| --- | --- | --- |
| 领域 | 高等数学 / 分析 / 代数 / 概率 / 其他 | 保留原三下拉为容错；选项含分类（树分类头不可点击，筛选栏可补） |
| 课程 | 13 门课程 | 保留 |
| 状态 | 探索中 / 已定稿 / 已完成 | 知识行状态，保留 |
| 流程（新增） | 全部 / 搜索 / 确认 / 下载 / 验收 | 书行级生命周期筛选 |

**流程 → 书行状态映射（用户裁决）：**

| 流程 | 书行状态 |
| --- | --- |
| 搜索 | candidate |
| 确认 | decided |
| 下载 | downloading / downloaded / failed |
| 验收 | verified |

- 流程筛选为**书行级**：知识行内仅显示匹配流程的书行；无匹配书行的教程行整行隐藏。
- 汇总文案更新（含流程过滤后的行数）。

**书行卡：**
- 去掉 kind 标签（与 roles 重复）；保留 状态（阶段）标签 + roles 标签 + 作者/版本/页数。

**书行排序（新纯函数 `sortBooks`，每教程行内）：**

1. 组序：① 中文教材（language=zh 且 kind=textbook）→ ② 中文习题集（language=zh 且
   kind=exercise）→ ③ 其余（英文教材、配套资料、论文等）。
2. 组内按册数递增：`part` 解析——第一册=1…第五册=5；上/中/下册=1/2/3；单册（part 空）=0
   排组首；答案册=99 排组尾。
3. 同册数按 title 稳定序。

### 2.3 教程命名（跨项目，请求：QED-Tracker）

- 规范：tutorial 知识行 `name = 教程{set_no}：{书名}（{作者}）`（书名作者取自教材决定
  引用 `textbook_ref`；en 套为「教程en：…」）；other_material 归类名不加「教程N」前缀。
- 存量：01 数学分析 3 行改名（套1 Rudin / 套2 菲赫金哥尔茨 / 套3 陈纪修，以 textbook_ref
  实际值为准）。
- 新建知识行默认命名同步（`migrate_knowledge.py` / `cli.py`）。
- 前端兜底：`tutorialLabel` 在 name 为空时显示「教程{set_no}」。

## 3. 范围与非目标

范围内（纯前端，本仓库实现）：
- `courseMeta.ts` 分类/领域常量；`downloads.ts` 树构建重构 + `sortBooks` + 流程筛选；
  `DownloadsTree.tsx` 新树渲染；`Downloads.tsx` 筛选栏/书行卡/排序；`downloads.css` 样式；
  相关测试同步。

非目标：
- 不请求 QED-Tracker 接口变更（教程名变更由其数据侧执行，前端 name 原样展示）。
- 不涉及后端 8900/8901 改动；不涉及学习中心（Knowledge.tsx）。
- 不拆分 en 套为独立教程行（当前 en 书行在套1 内，排序规则已将其置组尾，满足展示需求；
  是否拆行由 QED-Tracker 数据演进决定）。

## 4. 跨项目协作

教程命名规范为数据侧改动（请求：QED-Tracker）：根仓库登记 todo（请求：QED-Tracker）→
对方建设计文档 + todo 承接 → 用户评审 → 对方执行 → 回执。前端先行实现（name 未改前用
set_no 兜底显示），不阻塞本计划。
