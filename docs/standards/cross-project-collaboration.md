# 跨项目协作流程

状态：Current
最后更新：2026-08-09
治理对象：三项目间的需求传递、评审、执行与验收回执
依据 ADR：`docs/adr/0002-frontend-and-port-centralization.md`
关联测试：`tests/contract/test_cross_project_collaboration.py`

## 目的与边界

本标准规定根仓库（QED-Engine）与子项目（Axiom-Flow、QED-Tracker）之间协作需求如何提出、
评审、执行与验收。三个项目独立开发、独立部署，Axiom-Flow 与 QED-Tracker 是独立 git 仓库，
本仓库不直接修改其代码；任何跨项目改动必须由目标项目在其仓库内完成并遵守其门禁。

适用范围：任何需要对方项目配合的改动（服务端口、数据目录、直读配置变量、接口对接、前端
迁移等）。纯本仓库内的改动不适用本标准，走[任务生命周期](task-lifecycle.md)。

## 强制规则

### 流程步骤

1. **发起**：需求方在根仓库 `docs/trackers/todo.md` 登记请求任务（标注目标仓库与"请求"），
   变更涉及接口、端口、数据布局或契约时，在**对方项目**的 `docs/design/` 建设计文档
   （必要时先在对方仓库写 todo 请求条目）。
2. **评审**：用户评审对方仓库的设计文档与 todo 请求，确认方向；根仓库不直接修改对方项目
   代码。
3. **执行**：对方项目在自己的仓库内按自身 AGENTS.md 与门禁执行，由其 agent 或开发者完成
   （谁收任务谁执行）。
4. **验收回执**：对方完成并关闭其 todo 后，回到根仓库 todo 更新请求任务状态并记录证据
   （对方仓库的提交号/测试输出）。
5. **约束**：跨项目改动不得破坏独立性铁律；根仓库总台账保持与对方 todo 的一致性。

### 变更规模分级

| 规模 | 判定 | 必须产出 |
| --- | --- | --- |
| 接口/契约级 | 协议、端口、地址、字段、数据目录或配置事实源变化 | 对方项目设计文档 + 对方 todo 请求 + 根仓库登记 |
| 文案/操作级 | 文档措辞、命令示例、默认值说明 | 仅根仓库 todo 登记，可并入其他任务 |

### 设计文档模板

对方项目 `docs/design/` 中新建的设计文档至少声明：需求方、目标项目、接口面（端口/变量/目录/
协议）、评审方（用户）、执行方（目标项目）与验收标准。

### 登记格式

根仓库 todo 的跨项目请求行：任务列标注"（请求：<目标项目>）"；证据/下一条件列记录对方仓库
todo 承接情况与回执。

## 执行与门禁

- 涉及子项目改造的请求在根仓库 todo 登记，目标项目在自己的 todo 承接并遵守其门禁；根仓库
  不直接修改子项目文件。
- 请求被对方拒绝或改期时，根仓库 todo 更新为 Blocked 并声明证据、恢复条件与责任位置。
- 本条流程由 `tests/contract/test_cross_project_collaboration.py` 守护登记格式与设计文档模板
  的一致性；具体跨项目事实以双方 todo 与 Git 历史为准。

## 变更与取代

改变流程步骤、变更分级或登记格式时必须先新增 ADR。措辞、链接和不改变语义的流程整理可直接
修改本标准。子项目各自的协作流程以其自身 standards 为准；本标准作为三项目协作的上游约定。
